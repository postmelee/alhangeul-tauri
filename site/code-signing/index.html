Code signing policy

Alhangeul 코드 서명 정책 · 2026년 11월 14일

현재 상태

Alhangeul은 SignPath Foundation 지원 신청을 준비하고 있습니다. 아직 지원 승인이나 SignPath를 통한 코드 서명을 받지 않았습니다. 이 페이지는 후원 또는 서명 제공 사실을 알리는 페이지가 아닙니다.

현재 업데이트 파일의 Minisign 검증은 Windows Authenticode 코드 서명과 별개입니다. 지원이 승인되고 실제 서명 구성이 검증된 뒤 제공자와 적용 릴리스를 안내하겠습니다.

담당 역할

postmelee가 소스 작성(Author), 외부 기여 검토(Reviewer), 릴리스 서명 승인(Approver)을 담당합니다. 현재 한 명이 세 역할을 수행하므로 독립된 두 사람의 승인 체계를 의미하지 않습니다.

GitHub 접근에 MFA를 사용합니다. SignPath 계정을 도입할 때에도 MFA를 적용하고, 각 릴리스의 서명 요청을 담당자가 수동으로 승인하는 것을 운영 원칙으로 합니다. 현재 SignPath 계정이나 서명 자동화가 구성되었다는 뜻은 아닙니다.

서명 대상과 검토 원칙

서명 도입 시 Alhangeul 저장소에서 검토한 소스와 빌드 절차로 생성한 제품 실행 파일·설치 패키지를 대상으로 합니다. 고정한 의존성 출처와 제품명·버전, 빌드 결과의 동일성을 확인합니다. 외부 프로젝트의 독립 바이너리를 Alhangeul 소유 바이너리로 간주하지 않습니다.

구체적인 인증서·산출물 설정과 의존성 취급은 제공자의 심사 및 승인 후 확정합니다. 신청 준비는 지원 또는 인증서 사용 권한을 보장하지 않습니다.
