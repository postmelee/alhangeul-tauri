### 성능 결과의 조건과 한계

비교는 동일 VM, 1280×900/DPR 1, 두 renderer, 로컬 글꼴 off/on, 공개 문서 4종, 조건별 5회로 수행했다. 대표 Canvas2D/on 10쪽 HWPX의 warm open 중앙값은 Windows 18,255ms → 515.7ms, Linux 2,504ms → 636ms다. 웹 안내는 Windows 값을 0.516초로 반올림한다.

warm open은 최초 프로세스 시작 전체 시간이 아니다. 입력 batch부터 canvas 변화 확인까지의 PNG probe 비용을 포함한 Windows 입력 중앙값은 6,951.6ms → 106.6ms다. 물리 키 하나의 디스플레이 지연으로 해석하지 않는다. 같은 OS의 기준/개선 문서 첫 페이지 PNG 16쌍이 동일했다. 한컴 레이아웃 동등성·모든 글꼴·사용자 Wayland GPU 환경의 검증이 아니다.

성능 개선 제품은 `ef54ae9dd1de17a208eff6986335d23b2e7ff86b`, 비교 harness는 `8df43960d0b2d39b278b9566d9e294e9ba86c47a`다. 확정 main까지 해당 runtime diff가 없다는 #97 분석으로 기능 A/B 근거를 재사용하고, 새 main 파일의 설치 수용은 별도로 실행했다. 상세 원시 조건은 [#98의 Stage 3 고정 기록](https://github.com/postmelee/alhangeul-tauri/blob/28ae0a91f4bdc9f9b9552db48f8012aaaf4f58d7/mydocs/working/task_m010_97_stage3.md)에 보존돼 있다.

- 공개 키 fingerprint: `9f86f804067eff359cd32707137dfaaea8710450985dda86b0392da5db63b8f8`.
- [complete inventory](https://github.com/postmelee/alhangeul-tauri/releases/download/v0.1.1/alhangeul-updater-release-inventory.json): 2606 bytes, SHA-256 `8f594523bca49993ba3addc51346932ce0018b29533cf237987234f96eac9b82`.
- [SHA256SUMS](https://github.com/postmelee/alhangeul-tauri/releases/download/v0.1.1/SHA256SUMS): 976 bytes, SHA-256 `9e3bac3b575f8d074cae21a68dfcaa88e5b6205873996c3d0c4a379640745a44`, 자체를 제외한 10개 파일의 checksum.
- 서명은 각 NSIS/MSI/AppImage 고정 URL 뒤 `.sig`다. 이름·hash·서명 encoding은 원문 inventory와 공개 SHA256SUMS에 보존한다.
- #97에서 draft/public 두 개의 새 다운로드로 11개 파일을 검증했다. #102 Stage 3은 새 API의 ID/size/digest/URL과 보존한 공개 bytes 11개를 재대조하고, 작은 공개 파일 5개를 새로 다운로드해 hash·checksum 10행·Minisign 3종을 다시 검증했다. 이번 단계에서 대형 설치 파일 6개를 다시 내려받았다고 기록하지 않는다.
- Minisign은 updater payload 검증이며 Windows Authenticode 코드 서명을 대신하지 않는다. Windows 설치본은 Authenticode 미서명이다.
