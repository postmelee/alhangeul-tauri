## 실제 게시 파일 검증

Windows x64 NSIS·MSI, Linux x64 AppImage·DEB·RPM, Linux arm64 DEB를 해당 환경에서 설치하고 HWP/HWPX 편집·저장·재시작·재열기를 확인했습니다. Linux DEB의 직접 PDF·GTK/CUPS 인쇄·Nautilus/Thunar도 확인했습니다. RPM은 Fedora 44 QEMU/KVM Xfce X11, arm64는 Ubuntu 24.04 aarch64에서 검증했습니다.

전체 run·archive·파일 해시와 수용 범위는 [Stage 2](../../mydocs/working/task_m010_126_stage2.md), [Stage 3](../../mydocs/working/task_m010_126_stage3.md)에 있습니다. [Stage 4](../../mydocs/working/task_m010_126_stage4.md)는 draft/public 각각 11개 파일을 독립 다운로드한 결과와 실제 Minisign 3종 검증, 태그·본문 read-back을 기록합니다. 일반 Windows/AppImage를 서명 파일 대신 게시하지 않았으며 공개 과정에서 재빌드하지 않았습니다.

기존 NSIS 탐색기 썸네일 제한과 강제 MSI 3010 이후 재부팅 검증 미완료, Windows Authenticode 미서명은 유지합니다. 글꼴 폴백을 CanvasKit 전 구성 통과나 성능 개선으로 간주하지 않으며 모든 PDF 가져오기 옵션·배포판·Wayland·GPU·물리 프린터 조합을 검증한 것은 아닙니다. 상세 사용자 안내는 위 GitHub Release 본문에 있습니다.

## Alhangeul v0.1.3 릴리즈 후보

2026-11-11 기준으로 글꼴 재감지 회귀를 보정한 새 설치 파일 6종의 후보 검증을 마쳤습니다. 알려진 설치 제한은 아래에 구분해 기록했습니다. 현재 공개 버전은 [v0.1.2](v0.1.2.md)입니다.

### 사용자 안내 초안

#### 문서 편집과 저장

이번 후보는 문서 편집 엔진을 rhwp v0.8.7에서 v0.9.0으로 올립니다. 새 엔진은 중첩 표가 다음 쪽에 이어질 때 셀 여백과 줄 배치를 처리하는 방식을 개선했습니다. HWP나 HWPX를 저장하고 다시 열 때 표 앞뒤의 본문과 머리말·꼬리말이 보존되도록 보정했습니다. [rhwp v0.9.0 릴리즈 노트](https://github.com/edwardkim/rhwp/releases/tag/v0.9.0)

rhwp Studio는 PDF에서 가져올 쪽과 배치 방식을 선택할 수 있습니다. 원본 배치를 살리거나 편집하기 쉬운 배치를 선택할 수 있으며, 스캔한 글자를 인식하는 OCR은 지원하지 않습니다. 암호를 입력해 PDF를 열었더라도 가져온 문서에 원본 암호가 자동으로 설정되지는 않습니다. Alhangeul의 NSIS·MSI·AppImage 설치본에서 실제 PDF Worker로 1쪽 PDF를 가져오고, 반환된 HWPX를 같은 엔진으로 열어 텍스트를 확인했습니다. 모든 PDF 형식·배치 옵션을 수용했다는 뜻은 아닙니다.

#### Alhangeul 앱 변경

문서에서 요구하는 글꼴을 PC에서 찾을 때 글꼴 이름과 스타일을 함께 확인합니다. PDF 가져오기 작업도 편집 화면과 같은 버전의 문서 엔진을 사용하도록 연결했습니다. [글꼴·Worker 호환성 PR #123](https://github.com/postmelee/alhangeul-tauri/pull/123)

#### 설치 및 업데이트

빌드한 형식은 Windows x64의 NSIS·MSI, Linux x64의 AppImage·DEB·RPM과 Linux arm64의 DEB입니다. v0.1.3 설치 파일과 자동 업데이트는 아직 제공하지 않습니다. 첫 후보에서 글꼴 삭제 후 다시 감지해도 삭제 전 글꼴이 남는 문제를 확인했습니다. 새 후보는 선언 글꼴의 프로그램·CSS face·별칭을 함께 해제하며 설치본에서 삭제·복구 결과를 확인했습니다.

후보 검증 결과는 [Stage 4 인계 기록](../../mydocs/working/task_m010_122_stage4.md)에 연결합니다. 새 PR은 upstream 동기화 후보 #124의 커밋과 앱 보정을 함께 검토하는 통합 경로입니다. 병합·서명·공개 실행은 별도 승인 대상입니다.

첫 추가 검증 도구는 `e3d8a9522543ea937e5d6df51014d20b376b1149`다. v0.9.0은 Abel 공급을 끈 경우 `canvaskitResourcePreparationFailed`와 해당 글꼴 오류를 보고하고 Canvas2D로 전환한다. 해당 fixture의 비활성화 조건에만 이 명시적인 전환을 인정하며 실제 backend를 별도로 기록한다. Abel 공급 활성화 검사는 실제 CanvasKit 적용을 요구한다. 대표 문서가 기존 CSP로 차단된 외부 글꼴을 요청한 경우에는 브라우저가 보고한 차단 주소와 upstream 실패 URL을 대조하고 Canvas2D 전환으로 기록한다. 이 결과를 CanvasKit 실행 성공으로 집계하지 않는다. Windows 인쇄 취소는 성공했으며 출력 도구는 실제 창의 `Microsoft Print to PDF`·`Print` 선택으로 보정했다. 제품 bytes는 그대로다. 보정 도구 `2250d10986af10b0c7f3afaefc22c7373e6183fa`의 [빠른 CI](https://github.com/postmelee/alhangeul-tauri/actions/runs/42931953071)는 타입·자동화 1,368개·Windows PowerShell 검사를 통과했다.

일반 파일 재검사 `42932488095`는 AppImage의 외부 글꼴 차단 전환과 Windows 저장창의 파일명 입력 ID 전제에서 실패했다. 검증 도구 `1117cc0159a219bfdb2694ad6f5ffb627864bba5`는 실제 enforced CSP 증거를 수집하고 저장창의 `Edit/1001`을 정확히 선택한다. 로컬 타입 검사와 자동화 1,369개 및 [빠른 CI 42934577249](https://github.com/postmelee/alhangeul-tauri/actions/runs/42934577249)의 Node·Studio·Windows PowerShell 검사가 통과했다.

추가 시도 `42934573187`의 Windows 출력은 실제 6쪽 PDF로 생성됐으나 검사가 스풀러 쓰기보다 먼저 빈 파일을 읽었다. 하네스 `c5f59294abefb6ad3251bb5f6a5083283ff8c6e0`는 헤더와 PDF 끝 표시를 기다린다. HWPX의 미설치 한양신명조 전환은 문서 선언·upstream supply registry·native catalog를 독립 대조해 검증한다. 타입·자동화 1,370개 및 [빠른 CI 42936062390](https://github.com/postmelee/alhangeul-tauri/actions/runs/42936062390)를 통과했다. 해당 하네스의 최종 일반 파일 run `42936058653`은 세 형식 모두 성공했다. 이전 실패 run은 보정 이력으로 유지한다.

최종 NSIS·MSI Windows 시스템 인쇄의 실제 6쪽씩은 한글·표·쪽 구성을 시각 검토했다. Microsoft Print to PDF 출력에서는 검색 가능한 텍스트가 추출되지 않았다. 앱의 직접 PDF 내보내기에서 통과한 한글 검색과는 구분한다.

직접 PDF와 Linux 시스템 출력은 전체 페이지 개괄 및 대표 페이지 확대 검토에서 눈에 띄는 잘림·글자 누락을 발견하지 않았다. Windows 새 출력·재시작 덮어쓰기 32쪽, Linux 직접·GTK·CUPS 출력 28쪽의 렌더를 검토했다.

검증 도구 SHA·증거 archive ID/digest와 범위는 [Stage 3 보고서](../../mydocs/working/task_m010_122_stage3.md)에 연결했다. 후보 인계 산출물과 [최종 보고서](../../mydocs/report/task_m010_122_report.md)를 정리해 검토용 PR 단계로 넘겼으며, 서명 inventory 형식의 `v0.1.3.notes.json`은 실제 서명 파일 목록을 확보한 공개 준비 단계에서 작성한다.

새 빌드에서도 일반 MSI의 설치·제거와 Explorer 썸네일은 원시 결과가 성공이다. NSIS는 설치·제거 성공, 사용자별 Shell 썸네일 활성화 실패 12건이며 `thumbnailStatus=not-accepted`다. 강제 MSI 재설치는 재부팅 필요로 원시 실패 1건이고 재부팅 후 상태는 미검증이다. 해당 진단 계약의 성공을 기능 전체 수용으로 해석하지 않는다.
