# Alhangeul v0.1.3 릴리즈 후보

2026-11-10 기준으로 v0.1.3 후보는 Linux 설치본의 글꼴 재감지 회귀로 수용을 보류했습니다. 현재 공개 버전은 [v0.1.2](v0.1.2.md)입니다.

## 사용자 안내 초안

### 문서 편집과 저장

이번 후보는 문서 편집 엔진을 rhwp v0.8.7에서 v0.9.0으로 올립니다. 새 엔진은 중첩 표가 다음 쪽에 이어질 때 셀 여백과 줄 배치를 처리하는 방식을 개선했습니다. HWP나 HWPX를 저장하고 다시 열 때 표 앞뒤의 본문과 머리말·꼬리말이 보존되도록 보정했습니다. [rhwp v0.9.0 릴리즈 노트](https://github.com/edwardkim/rhwp/releases/tag/v0.9.0)

rhwp Studio는 PDF에서 가져올 쪽과 배치 방식을 선택할 수 있습니다. 원본 배치를 살리거나 편집하기 쉬운 배치를 선택할 수 있으며, 스캔한 글자를 인식하는 OCR은 지원하지 않습니다. 암호를 입력해 PDF를 열었더라도 가져온 문서에 원본 암호가 자동으로 설정되지는 않습니다. Alhangeul 설치본에서의 가져오기 동작은 다음 검증에 포함됩니다.

### Alhangeul 앱 변경

문서에서 요구하는 글꼴을 PC에서 찾을 때 글꼴 이름과 스타일을 함께 확인합니다. PDF 가져오기 작업도 편집 화면과 같은 버전의 문서 엔진을 사용하도록 연결했습니다. [글꼴·Worker 호환성 PR #123](https://github.com/postmelee/alhangeul-tauri/pull/123)

### 설치 및 업데이트

빌드한 형식은 Windows x64의 NSIS·MSI, Linux x64의 AppImage·DEB·RPM과 Linux arm64의 DEB입니다. v0.1.3 설치 파일과 자동 업데이트는 아직 제공하지 않습니다. Linux에서 사용 중인 글꼴을 삭제하고 다시 감지해도 같은 창에서 삭제 전 글꼴로 보이는 문제가 확인됐습니다.

### 대표 설치본의 실제 결과

- **Windows x64 NSIS**로 HWP 6쪽·HWPX 10쪽 문서를 열고 편집한 후 직접 PDF로 내보냈다. 새 세션과 재시작 후 덮어쓰기 모두 4건의 페이지 수·한글 텍스트·원본 해시 검사가 통과했다. [Windows PDF 실행](https://github.com/postmelee/alhangeul-tauri/actions/runs/42751850219)
- **Linux x64 DEB**에서 HWP/HWPX 열기·저장·재열기와 직접 PDF 검사가 통과했다. GTK 파일 인쇄·CUPS-PDF 출력·인쇄 취소 후 편집 복귀, Nautilus·Thunar의 HWP/HWPX 첫 요청·캐시 재사용·파일 변경 후 썸네일 재생성도 확인했다. [Linux GUI 실행](https://github.com/postmelee/alhangeul-tauri/actions/runs/42751853554)
- **Linux 글꼴 재감지 실패.** Abel을 설치한 뒤 두 문서에 적용하는 데 성공했지만, 글꼴 파일을 삭제하고 다시 감지하면 로드된 Abel face가 1개 남았다(기대 0개). Canvas2D에서는 페이지 픽셀도 삭제 전과 같았다. CanvasKit을 요청한 시나리오도 같은 검사에서 실패했고, 삭제 직후 진단은 Canvas2D를 보고했다. 복구·비활성화·재시작으로 이어지는 해당 시나리오는 미수용이다. [글꼴 실행](https://github.com/postmelee/alhangeul-tauri/actions/runs/42751857930)
- **남은 범위.** 일반 AppImage 직접 실행, Fedora RPM·arm64 DEB의 실제 GUI 문서 작업, 설치본에서 폼·PDF 가져오기 Worker 실행과 Windows 시스템 인쇄 검증이 남았다. Windows 일반 MSI 재설치 및 Linux DEB·RPM 패키지 검증 결과와 각각 구분한다.
