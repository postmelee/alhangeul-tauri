## 사용자 문구 초안과 포함 PR

아래 문구는 릴리즈 안내 준비용이다. 새 설치 파일의 검증·배포 성공을 뜻하지 않는다.

### 변경 요약

rhwp v0.8.7을 반영해 표와 문단의 조판, 문서 열기·저장·편집 개선을 포함합니다.
Alhangeul의 창 제목과 접근성 이름을 제품명으로 유지하고 새 글꼴 공급 API와 연결합니다.

### 포함된 rhwp 변화

- 문단 안 연속 표의 너비·줄바꿈과 중첩 표·행 병합 표의 페이지 분할을 보정했습니다.
- 빈 머리말·꼬리말이 있는 HWP 저장본과 반복 표 제목·쪽 경계 설정의 저장을 보정했습니다.
- Studio 영어 UI, 웹 하이퍼링크 편집, 덮어쓰기 모드와 찾기 결과 개수 표시를 추가했습니다.
- 표 뒤 Enter와 중첩 표의 선택·삭제·붙여넣기, 글꼴 공급 및 문서 입력 경계의 처리를 보강했습니다.

이 목록은 [upstream v0.8.7 공식 릴리즈](https://github.com/edwardkim/rhwp/releases/tag/v0.8.7)의
제품 관련 변화 요약이다. CLI·브라우저 확장·다른 OS의 배포 변화는 Alhangeul 변경으로 넣지 않는다.
문서 형식의 모든 취약점 해결이나 모든 문서·PC의 표시 개선을 보장하지 않는다.

### Alhangeul 앱 변화

- 기존 로컬 글꼴 선택·이름별 조회·파일 읽기 캐시를 새 upstream renderer API에서도 공유합니다.
- 새 upstream 시작·문서 제목 처리에서도 Alhangeul 제품명을 유지합니다. native 문서의 수정 상태
  표시는 기존 문서 세션이 관리하고, 접근성 이름은 한국어·영어 초기화에 맞춥니다.

- CanvasKit 표시 모드에서 로컬 글꼴 파일을 삭제한 뒤 다시 감지할 때 페이지가 비어 보이던
  문제를 보정했습니다. 새 source의 Linux 설정·삭제/복구·새 창·재시작 GUI를 수용했습니다.

기존 v0.1.1의 성능 수치를 새 pin의 측정 결과로 복사하지 않는다. 자동 후보 관리 참조와 게시 전
검증 보정, 버전 번호·운영 기록 변경은 사용자 주요 신규 기능으로 나열하지 않는다.

### 지원·설치·업데이트 안내 초안

Windows x64와 Linux x64를 지원하며 Linux arm64는 DEB 형식을 준비합니다. Windows에는
WebView2 Runtime이 필요합니다. Windows는 NSIS/MSI, Linux x64는 AppImage/DEB/RPM 중
환경에 맞는 형식을 선택합니다. AppImage는 실행 권한과 파일·폴더 쓰기 권한이 필요합니다.

Windows NSIS·MSI와 Linux x64 AppImage는 앱 시작 시 또는 제품 정보에서 새 버전을 확인합니다.
다운로드·설치는 사용자가 선택하며 저장하지 않은 문서가 있으면 먼저 저장하도록 안내합니다.
DEB·RPM·Linux arm64는 배포판에 맞는 새 패키지를 수동으로 설치합니다.
현재 v0.1.2는 공개되지 않았고 0.1.1 → 0.1.2 업데이트 수용은 아직 실행하지 않았습니다.

### 알려진 제한 문구 초안

Windows 설치 파일은 기존 정책상 Authenticode 미서명이며 자동 업데이트용 Minisign과는 별개입니다.
일부 Windows NSIS 환경의 탐색기 썸네일 제한과 강제 MSI 설치 후 재부팅 미검증은 이전 공개
버전의 기록입니다. 새 v0.1.2 파일에서 해당 범위를 다시 확인하기 전 해결로 표시하지 않습니다.
사용자의 모든 Wayland·GPU·글꼴·문서·배포판·물리 프린터 조합은 검증하지 않았습니다.

### 짧은 updater 안내 초안

rhwp v0.8.7의 표·문단 조판과 열기·저장·편집 개선을 반영합니다. 새 글꼴 공급 API와 제품
창 제목·접근성 이름을 Alhangeul에 연결합니다. Windows/Linux 새 설치 파일과 앱 내 업데이트는
검증·공개 준비 중입니다. 자세한 변경과 설치 안내는 v0.1.2 릴리즈 노트를 확인하세요.

## 산출물 provenance와 공개 gate

설치 파일은 Windows x64 NSIS/MSI, Linux x64 AppImage/DEB/RPM, Linux arm64 DEB의 6종이다.
최종 updater 3종은 같은 exact source의 한 nonpublishing signed producer에서 선택하고,
수동 3종은 같은 source의 일반 producer에서 선택한다. 현재 FF 검증 후보의 실제 파일 이름·size/hash·archive digest·signature·inventory·draft body hash를
[3.2 기록](../../mydocs/working/task_m010_113_stage3.2.md)에 확정했다. 최종 main의 새 bytes는 이후 gate다.

2026-10-08 작업지시자가 “기존 규격 유지·JSON 완성 이연 (권장)”을 선택했다. draft notes도 실제
6개 파일과 3종 updater inventory를 요구하므로, 이 문구 준비 뒤 해당 검증을 끝내고
`v0.1.2.notes.json`·생성물을 완성한다. 가상 metadata를 채우거나 validator를 완화하지 않는다.
