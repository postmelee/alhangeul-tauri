## 포함 범위와 변경 요약 초안

- Windows/Linux에서 HWP/HWPX 열기·편집·형식별 저장·재열기, 직접 PDF와 시스템 인쇄.
- Windows MSI·NSIS의 Explorer 첫 페이지 썸네일과 Linux DEB/RPM의 파일 관리자 썸네일.
- Windows MSI·NSIS, Linux x64 AppImage의 서명된 동일 형식 updater 및 별도 Pages.

이번 계획의 썸네일 포함은 작업지시자의 최신 요청을 따른다. 과거 #14·#24 보고서의
‘첫 릴리즈 필수 범위에서 제외’는 당시 결정으로 보존하며 현재 공개 범위 판단에 재사용하지 않는다.
위 목록은 예정 기능 요약이다. 공개 notes의 최종 표현은 candidate와 아래 한계를 확인한 뒤 확정한다.

| 9 | 첫 공개 설치본 보존과 후속 upstream·다음 릴리즈 담당 | 작업지시자; MSI/NSIS 격리·writable AppImage 기준선 및 후속 Issue | Gate 7, 실제 업그레이드 성공 주장 금지 |

현재 마지막 일반 native 수용 SHA는 위 근거 목록의 `50e9124…`다. #54 merge 후의 후보까지
runtime/config/pin/검사 도구 diff를 다시 판정한다. 문서-only라면 기존 source 수용을 재사용할
수 있지만 새 installer hash·서명·설치 기본 확인을 대신하지는 못한다. 열린 모든 Issue를
릴리즈 선행 조건으로 삼지 않고 위 결정과 실제 변경 영향에 필요한 항목만 선택한다.

각 Gate는 [실행 가이드](../operations/PUBLIC_RELEASE_RUNBOOK.md)를 따르고 결과는 이 기록의
identity·검증·공개 gate·한계 항목에 갱신한다. 아직 실행하지 않은 항목은 미실행으로 남긴다.

### 첫 공개 이후 순서

1. Task #54 문서 PR merge 뒤 #9의 범위·결정·필수 수용을 최신 요청으로 재정렬한다.
2. 승인한 v0.1.0 후보에 썸네일·Pages·MSI/NSIS/AppImage updater를 포함해 첫 공개를 진행한다.
   현재 검증된 rhwp v0.8.4 유지 여부도 이때 승인하며 세 형식의 첫 설치본을 보존한다.
3. [macOS sync PR #491](https://github.com/postmelee/alhangeul-macos/pull/491)은 참고만 한다.
   2026-09-04 기준 OPEN이며 Tauri PR이 아니다. 별도 Tauri Task에서 rhwp v0.8.6 Stable tag·
   resolved commit·core·Studio·WASM 정합성과 영향 검증을 수행한다.
4. 다음 앱 version은 별도 승인한다(`0.1.1`은 제안값). 새 공개 후 세 설치 형식의 실제
   production 업그레이드·재실행을 확인하고 이 기록과 다음 버전 기록을 연결한다.

첫 공개 전에 필요한 기본 설치·문서 기능 확인을 다음 버전의 updater 시험으로 미루지 않는다.
이번 단계에는 서명·workflow dispatch·release/tag·Pages 배포·Secret 설정 변경이 없다.
