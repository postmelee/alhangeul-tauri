# README 배지와 운영체제별 홈페이지 안내 수행계획서

GitHub Issue: [#90](https://github.com/postmelee/alhangeul-tauri/issues/90)
마일스톤: M010

## 목적

README 첫 화면에서 알한글 릴리즈와 포함된 rhwp 버전을 확인할 수 있게 한다.
Windows·Linux 및 MIT 배지를 함께 배치하고 실제 고정 버전과 자동 동기화의 정합성을 유지한다.
Windows/Linux 홈페이지에서 별도 macOS 홈페이지를 찾을 수 있도록 상호 안내를 추가한다.

## 배경

현재 공개 안정 릴리즈는 v0.1.0이고 rhwp-core.lock은 v0.8.6/f1f9c6ae로 고정돼 있다.
README는 #85에서 사용자 안내로 정리됐고 #87 이후 공개 기본 브랜치는 main이다.
기존 managed-reference updater는 README 하단 Stable pin만 갱신하므로 새 배지도 관리해야 한다.
PR #91 게시 후 작업지시자가 macOS 홈페이지 링크와 macOS 프로젝트 새 세션의 반대 링크·배지
작업 지시를 요청했다. 열려 있는 #90의 사용자 안내 보완 범위에 Stage 4로 반영한다.

## 범위

### 포함

- 제목 아래 배지 4개: 알한글 최신 안정 릴리즈, 포함 rhwp, Windows·Linux, MIT.
- rhwp 표시값·alt·tag 링크를 함께 바꾸는 기존 managed-reference 규칙과 회귀 검증.
- 이슈·계획·단계·최종 보고·devel 대상 PR 및 GitHub 실제 README 확인.
- 홈페이지·업데이트·문의 헤더의 ‘알한글 for macOS’ 링크와 좁은 화면 배치 보완.
- 모바일에서는 상호 링크를 홈 다운로드 아래·하위 페이지 푸터로 옮기고 헤더를 한 행으로 복원.
- 기존 Pages·제품 경계 검사에서 승인된 외부 링크 문장만 source/output의 세 페이지에 허용.
- 별도 macOS 프로젝트 새 세션에 rhwp 배지·‘알한글 for Windows / Linux’ 링크 작업 전달.

### 제외

- rhwp pin·제품 코드·lock·workflow·Release/tag·설치본 변경.
- 승인된 상호 안내 이외 사이트 내용·다운로드·updater 변경 및 macOS 저장소 직접 구현.
- 새 CI/설치본 빌드, PR 병합·main 승격·릴리즈 게시.

## 설계 방향

알한글 배지는 GitHub 안정 릴리즈를 조회하고 다운로드 페이지로 연결한다. rhwp 배지는
업스트림 최신 릴리즈나 다른 브랜치의 lock을 조회하지 않고 이 README에 대응하는 고정 tag를
표시한다. 기존 동기화의 exact marker 검증에 전체 배지 Markdown을 포함해 표시와 링크를
동시에 갱신하고, marker 불일치 시 어떤 파일도 쓰지 않는 경계를 유지한다.
플랫폼·라이선스는 정적 배지이며 각각 설치 페이지·기존 LICENSE로 연결한다.
홈페이지 상호 링크는 데스크톱 nav의 일반 링크로 유지한다. 520px 이하에서는 기존 세 메뉴와
브랜드를 한 행으로 배치하고 상호 링크를 홈 다운로드 아래·하위 페이지 푸터에 보조 안내로 둔다.

## 검증 계획

- Stage 1: git diff --check, 배지 4개 SVG HTTP 200·표시값, lock와 원문 보존 확인.
- Stage 2: managed-reference·sync focused tests, pnpm run check:product-boundary,
  pnpm run test:upstream. 후보 tag 전환과 marker 실패 시 무쓰기 확인.
- Stage 3: diff 허용 범위·제품 경로 불변, 원격 README 이미지와 링크, PR base/head 확인.
- Stage 4: pnpm run build:pages·check:pages, 기존 Pages tests, 로컬 실제 desktop/320px 화면,
  외부 목적지 접근·세 페이지 링크·다운로드 유지·제품/pin/manifest 불변 확인.
- Stage 4 추가: 기존 검사가 macOS 식별자를 전부 금지하므로, exact 링크 문장과 승인 경로만
  허용하고 다른 줄의 제품 표현·변경된 목적지·다른 소스 파일은 계속 검출하는 회귀 검증을 수행한다.
- Stage 5: Pages build/check·기존 Pages/경계 tests·product-boundary·diff 검증, 320/390/520px
  홈과 320px 하위 페이지·521/1280px 헤더·링크 목적지 확인, release/manifest 불변 확인.
- 경계 검사·기존 테스트는 exact 보조 안내 등록으로 300 LOC를 소폭 초과할 수 있다.
  역할이 같은 예외 데이터와 기존 실패 사례에 한정하고 CSS를 그대로 따라 하는 테스트는 추가하지 않는다.
- 네 배지 정상 렌더링, rhwp 표시/링크/pin 정합성, clean 작업 트리로 PR 준비를 수용 기준으로 둔다.

## 승인 범위

작업지시자의 README 상단 배지·포함 rhwp 버전 추가 요청 범위에서 필요한 관리 참조 보완과
검증을 진행한다. 작은 사용자 문서 보완은 충돌 규칙의 축소 절차를 적용하되 이슈와 단계 기록을
남긴다. 검토 가능한 PR까지 준비하고 병합·공개 main 반영은 별도 명시 지시를 따른다.
추가 지시 “홈페이지 헤더 … 알한글 for macOS … 새 세션에게 … 지시”를 Stage 4의
사이트 문서 위치·수정·검증·세션 생성 승인으로 기록한다. 공개 배포와 병합은 실행하지 않는다.
추가 지시 “그렇게 적용해서 나에게 보여줘”는 Stage 5의 모바일 배치·문서 위치·검증·미리보기
및 기존 PR 갱신 승인이다. macOS 기존 세션에도 같은 모바일 안내 방향을 전달한다.
