# Task #34 수행계획서 — Linux exact-SHA GUI acceptance 자동화

GitHub Issue: [#34](https://github.com/postmelee/alhangeul-tauri/issues/34)
마일스톤: M010

## 목적

공개 저장소의 표준 GitHub-hosted native Linux x64 runner에서 Alhangeul의 실제 배포 bundle을 설치하고, 열기·저장·PDF·system print와 핵심 화면 상태를 반복 검증하는 exact-SHA GUI acceptance gate를 구축한다.

검증 대상 SHA와 native workflow run/artifact metadata를 fail-closed 방식으로 결속하고, 판정 근거가 되는 화면·PDF·로그·환경 정보를 증거 artifact로 보존한다. Issue #35가 Windows adapter를 추가할 수 있도록 WebDriver와 문서 검증 경계는 플랫폼 중립으로 만들되 Linux GTK native UI 조작은 별도 adapter로 격리한다.

## 배경

Issue #24의 rhwp v0.8.4 후보는 Windows x64 검증을 통과했지만 Linux GUI 검증이 Apple Silicon macOS의 Colima x86_64 VM과 수동 조작에 의존했다. 이 경로는 QEMU 에뮬레이션과 대형 artifact 재다운로드 때문에 반복 후보 판정에 비효율적이다.

Tauri 공식 WebDriver 문서는 Linux에서 `tauri-driver`, WebKitWebDriver와 Xvfb를 이용한 CI 검증을 지원한다. 다만 WebDriver는 WebView DOM을 담당하므로 GTK 파일·인쇄 대화상자와 OS drag-in은 AT-SPI 계열 native UI adapter가 별도로 필요하다. 제품에 WebDriver 전용 플러그인을 포함하는 embedded 방식보다 설치된 배포 binary를 외부 `tauri-driver`로 구동하는 방식을 우선 검증한다.

공식 반복 gate는 무료 표준 GitHub Actions runner에 둔다. Codespaces는 CI 실패의 일회성 재현에만 선택적으로 사용하며 무료 한도를 확인할 수 없거나 소진하면 유료 전환 없이 중단한다.

## 설계 방향

- **배포 binary 우선**: native build workflow가 만든 exact-SHA Linux x64 artifact의 DEB를 설치하고 `/usr/bin/Alhangeul`을 외부 `tauri-driver`로 구동한다. Stage 1에서 이 경로가 기술적으로 불가능하다고 확인되면 embedded plugin으로 자동 전환하지 않고 계획 변경 승인을 요청한다.
- **별도 수용 workflow**: `.github/workflows/alhangeul-linux-gui.yml`을 수동 `workflow_dispatch` gate로 두어 native bundle을 재빌드하지 않고 지정 run의 artifact를 검증한다. 입력은 `build_ref`와 native `run_id`를 필수로 하고 임의 최신 artifact 선택을 금지한다.
- **fail-closed handoff**: checkout된 `HEAD`, 입력 SHA, native workflow run의 `head_sha`, artifact metadata와 package inventory/checksum 중 하나라도 불일치하면 설치 전에 실패한다. 다른 repository·branch의 artifact나 이름만 일치하는 artifact는 허용하지 않는다.
- **경계 분리**: WebView DOM과 제품 bridge 검증은 WebdriverIO 공통 spec/helper에 두고, GTK dialog·drag-in은 Linux native UI adapter로 분리한다. 공통 fixture·evidence schema·handoff verifier는 Issue #35가 재사용할 수 있게 플랫폼에 종속되지 않게 유지한다.
- **native UI 자동화**: 우선 AT-SPI의 접근성 role/name 기반 semantic 조작을 사용한다. 접근성 tree로 식별할 수 없는 제한된 구간만 명시적 timeout과 화면 증거를 갖춘 입력 fallback을 허용하며 좌표 고정은 기본 설계로 삼지 않는다.
- **결과 검증**: PDF는 `pdfinfo`, `pdftotext`, 페이지 render를 조합해 쪽 수·A4·한글 text·빈 쪽·잘림을 자동 판정한다. 한글 glyph/tofu와 대표 페이지 배치는 고정 runner의 screenshot evidence를 함께 남기고 Stage 5 canary에서 사람이 최종 읽어 자동 판정의 신뢰도를 확인한다.
- **증거 보존**: 성공·실패 모두 `always()` 조건으로 screenshot, 생성 PDF, bounded log, 환경 version과 JSON summary를 올린다. 사용자 개인 문서·경로·secret은 사용하거나 기록하지 않는다.
- **비용 경계**: 공식 gate는 public repository 표준 GitHub-hosted runner만 사용한다. Codespaces 절차를 문서화할 경우 prebuild와 paid fallback을 금지하고 무료 allowance 확인, 짧은 idle timeout, 즉시 삭제를 요구한다.
- **#24/#35 순서**: #34 merge 후 #35를 진행하고, 두 자동화가 merge된 뒤 #24를 최신 `devel`의 새 exact SHA에서 Stage 3부터 재검증한다.

## 리스크

- **WebDriver와 native dialog 경계**: WebDriver만으로 GTK dialog를 제어할 수 없다. AT-SPI adapter를 별도 경계로 두고 Stage 1에서 접근성 tree와 안정성을 먼저 측정한다.
- **배포 binary 연결 불가**: 외부 `tauri-driver`가 설치된 production binary에 연결되지 않을 수 있다. embedded plugin을 몰래 포함하지 않고 즉시 중단해 계획 변경 승인을 요청한다.
- **cross-run artifact 오결속**: 이름만 같은 최신 artifact를 받으면 다른 SHA를 검증할 수 있다. run metadata, exact checkout, inventory와 checksum을 모두 확인하고 불일치 시 설치 전 실패한다.
- **runner 환경 변동과 flaky UI**: 창 focus·애니메이션·CUPS timing이 실패를 만들 수 있다. semantic selector, readiness condition, bounded timeout과 진단 artifact를 사용하고 무조건 재시도로 실패를 숨기지 않는다.
- **한글 시각 판정의 취약성**: text extraction만으로 glyph tofu를 검출할 수 없다. 자동 text·page 계약과 고정 환경 screenshot을 함께 보존하고 Stage 5에서 시각 증거를 확인한다.
- **workflow 비용·시간**: 대형 bundle 재다운로드와 전체 GUI가 runner 시간을 소모한다. manual gate, concurrency cancellation, 최소 필요 artifact와 명시적 timeout을 사용하며 유료 runner로 우회하지 않는다.
- **Issue #27과 Action reference 중첩**: 기존 workflow 전체 pin 갱신은 건드리지 않고 이번 task가 새로 도입하는 reference만 immutable SHA로 고정한다.

## 승인 요청 사항

- 설치된 exact-SHA DEB를 외부 `tauri-driver`로 검증하고, embedded WebDriver plugin은 Stage 1 실패 후 별도 계획 변경 승인 없이는 도입하지 않는 방향
- 별도 manual Linux GUI workflow에서 `build_ref`와 native `run_id`를 필수 입력으로 받는 fail-closed handoff
- WebDriver 공통 경계와 Linux AT-SPI native UI adapter를 분리해 Issue #35가 공통 harness를 계승하는 구조
- 자동 PDF/text/page 판정과 screenshot evidence의 Stage 5 시각 read-back을 결합하는 한글·배치 수용 방식
- 공식 gate는 무료 표준 Actions runner로 한정하고 Codespaces는 무료 조건이 확인된 선택적 디버깅에만 사용하는 비용 경계
- #34, #35 merge 후 #24를 새 exact SHA에서 재개하는 작업 순서

승인되면 `task_m010_34_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
