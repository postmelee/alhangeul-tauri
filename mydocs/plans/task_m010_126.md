# Task #126 수행계획서 — Alhangeul v0.1.3 공개

GitHub Issue: [#126](https://github.com/postmelee/alhangeul-tauri/issues/126)  
마일스톤: M010 · 2026-11-11

## 목적

검증된 rhwp v0.9.0 기반 Alhangeul v0.1.3을 공개하고, v0.1.2에서 동일 설치 형식의 실제 업데이트까지 완료한다.

## 배경

#122와 PR #125의 후보 검증이 완료됐고 devel은 `2b055bb4066b9d3555b74f20bdf895740c76d61a`다. 이전 main/공개 v0.1.2 소스는 `6dcb05e96ec2075d09d8a60160e1d82f08c0811b`다. 현재 main 대비 devel 37개 커밋에는 이전 공개 후 운영 기록과 #122가 포함된다. 제품 소스의 이후 문서 변경을 native 검증 SHA와 혼동하지 않는다.

## 범위

### 포함

- devel → main 일반 릴리즈 PR, 최종 main exact SHA 고정.
- 같은 최종 SHA의 일반 패키지와 비게시 production updater 서명 후보 생성. 게시할 6개 installer, 3개 signature, complete inventory, SHA256SUMS를 검증한다.
- 실제 inventory로 notes JSON·본문·HTML을 생성하고, 검증한 bytes 그대로 maintainer CLI의 draft/read-back/stable 순서로 게시한다.
- release data PR·Pages·stable manifest, 공개 HTTP/화면, 실제 v0.1.2 → v0.1.3 NSIS/MSI/AppImage 업데이트.
- 기록·최종 보고·PR·이슈 종료와 부산물 정리.

### 제외

추가 upstream 갱신, 신규 제품 기능·OS·형식, 키 교체, 태그 이동·force push·asset 덮어쓰기. Mac의 Rust/Tauri 빌드는 수행하지 않는다.

## 설계 방향

기존 PUBLIC_RELEASE_RUNBOOK Gate 0~7, RELEASE_CHECKLIST, CI_VALIDATION의 검증 순서를 유지한다. 기존 키·endpoint·환경 보호를 유지한다. 파일은 최종 main으로 1회 생성하고 새 bytes의 설치·무결성은 다시 확인한다. #122의 동일 runtime 기능 증거는 diff 근거로 재사용하며 전체 성능·negative suite를 임의 반복하지 않는다. release PR은 기존 devel을 main으로 승격하고 작업 문서/검증 입력은 local/task126 → publish/task126 → devel 경로로 통합한다.

기존 NSIS hosted 사용자별 Shell 썸네일 실패와 강제 MSI 3010/재부팅 후 미검증은 이미 공개 v0.1.2에 기록된 한계다. 새 파일에서 동일 패턴인지 원시 결과를 확인하고 MSI 대안·한계를 안내한다. 이를 해결 또는 썸네일 전체 통과로 기록하지 않는다. 새 혼합 실패나 필수 문서/업데이트 실패는 공개 전에 회복한다. 기존 공개 정책을 변경하는 새로운 위험 수용은 별도로 판단한다.

## 검증 계획

### 단계별 검증

- Stage 1: live refs/releases/환경 정책, PR diff·트리·pin, 기존 PR #125 required 42951652590 성공과 source 차이. main PR에 없는 required를 있다고 주장하지 않는다.
- Stage 2: 일반 producer all/full/run_tests=true, updater publish_release=false, 동일 workflow/build/checkout SHA; Windows/Linux에서 Rust·패키지·필수 job 검사. archive ID/digest/만료와 실제 installer 크기/hash, production key fingerprint/서명3·inventory를 대조한다.
- Stage 3: 기존 release-file, release-linux-file, release-fedora-vm 수용으로 NSIS/MSI/AppImage·DEB/RPM/arm64 새 bytes의 설치·문서 저장/재열기·version 확인. #122와 코드 불변인 PDF/시스템 인쇄·글꼴 삭제복구 기능 근거는 재사용하고 새 파일 provenance는 구분한다. notes/Pages 계약·타입·집중 회귀 및 PR required 검사.
- Stage 4: tag peeled SHA, draft와 public의 11개 파일 크기/hash, 서명·inventory, body exact UTF-8 read-back, latest stable 상태.
- Stage 5: 같은 원문 body/HTML/short notes, build/check Pages, 공개 manifest와 output 동일, desktop/mobile 링크·줄바꿈·다운로드6개. production upgrade의 동일형식 실제 설치/재실행/version·문서·설정 보존과 cleanup 확인.
- Stage 6: 결과 문구·기록 링크·공개 상태, 필요한 notes/Pages 계약과 exact PR checks. 기술 기록 PR 후 일반 merge·close·cleanup.

### 통합 검증

실제 게시 bytes와 수용 bytes가 같고 source/pin/key/endpoint가 일치한다. 공개 완료와 자동 업데이트 완료를 개별 증거로 확인한다. diff 검사 통과와 PR 전 clean tree를 유지한다. private 증거는 T7 output에 보존하고 로컬 경로·비밀은 커밋하지 않는다.
