# Task #24 수행계획서 — rhwp v0.8.4 core·전체 Studio bundle 동일 release 갱신

GitHub Issue: [#24](https://github.com/postmelee/alhangeul-tauri/issues/24)

## 목적

선행 Task #23의 실제 자동 동기화가 만든 draft candidate를 감사 가능한 고정 입력으로 사용해 Alhangeul의 Rust core, 읽기 전용 upstream source, bundled WASM과 전체 `rhwp-studio`를 `rhwp v0.8.4` 하나로 갱신한다.

자동화와 Ubuntu 플랫폼 중립 검증만으로 제품 수용을 선언하지 않는다. v0.8.2→v0.8.4 source·release 변경과 Tauri leaf adapter 영향을 검토하고, 최종 exact SHA에서 Windows x64와 Linux x64 native 기능·패키징을 다시 검증한다. Linux arm64는 native bundle·inventory·checksum을 검증하되 실제 GUI를 실행하지 못했다면 그 한계를 명시한다.

## 설계 방향

- **candidate 불변성**: PR #32의 head `b3712714...`를 이동·force-push·수정하지 않는다. parent가 task-start 기준 `origin/devel`과 같고 13개 allowlist 경로만 바뀐 상태를 다시 확인한 뒤, 계획 승인 후 exact commit을 `local/task24`의 명시적 merge parent로 연결한다. task-start 문서 commit이 이미 존재하므로 단순 fast-forward가 불가능하며, cherry-pick·rebase·재생성 대신 non-fast-forward merge로 bot author와 원본 commit SHA를 보존한다.
- **단일 release 원자성**: source gitlink, native Cargo lock, generated WASM package와 `rhwp-core.lock`을 일부만 채택하지 않는다. verifier가 tag `v0.8.4`, commit `496333b...`과 모든 관리 artifact hash를 동시에 검증해야 한다.
- **전체 Studio 상속**: Vite root와 entry는 계속 `third_party/rhwp/rhwp-studio`를 사용한다. upstream Toolbar·Canvas·renderer·dialog·style을 local 복제하지 않고, Tauri 고유 filesystem·save/export/print·window/font 경계에 필요한 기존 leaf adapter만 유지한다.
- **영향 기반 최소 보정**: release/source diff에서 바뀐 native 또는 Studio surface를 먼저 분류하고 기존 adapter test로 회귀를 재현한다. 제품 코드 보정은 실제 Windows/Linux 차이로 입증된 최소 범위만 허용하며 upstream engine·renderer 결함은 이 task에서 직접 고치지 않는다.
- **exact-SHA gate**: 플랫폼 중립 CI가 통과한 하나의 실행 가능 SHA에서 native matrix를 수행한다. 이후 실행 코드·workflow·official operations 문서가 바뀌면 영향에 따라 같은 gate를 다시 실행하고 최종 증적 SHA를 갱신한다.
- **플랫폼 판정 분리**: Windows x64와 Linux x64는 실제 앱 GUI와 system dialog까지 확인한다. Linux arm64는 hosted runner의 build·inventory·checksum까지만 Go로 판정하고 native GUI 미검증을 공개적으로 기록한다.
- **candidate disposition**: Task #24의 `publish/task24` PR에 candidate commit과 수용 보정·증적이 모두 포함된 뒤에만 PR #32를 “#24가 supersede”하는 후보로 판단한다. PR #32 close는 작업지시자 승인 또는 Task #24 merge 확인 뒤 수행하며 직접 merge하지 않는다.
- **배포 경계**: Actions artifact는 수용 검증용이며 공개 release asset이 아니다. release·tag·서명·업dater는 별도 승인 없이는 수행하지 않는다.

## 리스크

- **generated artifact의 대형 diff**: WASM JS·binary와 Cargo lock 변화가 커서 눈검토만으로 정합성을 보장할 수 없다. 자동 생성 provenance, exact source commit, pin hash와 재현 검증을 함께 사용한다.
- **core·Studio 혼합 release**: 일부 파일만 보정하면 API와 bundle이 어긋날 수 있다. candidate를 원자적으로 채택하고 pin verifier를 모든 stage의 선행 gate로 둔다.
- **adapter surface drift**: v0.8.4가 save·print·render API를 바꾸면 compile 성공과 실제 UX가 다를 수 있다. source diff와 boundary test 뒤 Windows/Linux GUI를 별도 판정한다.
- **upstream known issue 오분류**: v0.8.2 기록을 v0.8.4에 자동 승계하지 않는다. 동일 fixture·조건·실패 지점을 확인할 때만 known issue로 분류하고 다른 실패는 Alhangeul 회귀 후보로 둔다.
- **hosted runner 비용·drift**: native matrix는 CI 통과 뒤 한 exact SHA에서 실행하고 실패 job부터 분석해 불필요한 반복을 피한다.
- **수동 GUI 환경 차이**: Windows VDI와 Linux GUI 환경이 실제 사용자 장치 전체를 대표하지 않는다. 자동 package smoke와 대표 수동 smoke의 범위·환경·미검증 항목을 함께 기록한다.
- **중복 PR**: PR #32와 Task #24 PR이 같은 base diff를 제안할 수 있다. #32를 immutable input으로 유지하고 Task #24 PR 게시 시 superseded 관계를 명시하며, 승인 전 close·merge하지 않는다.
