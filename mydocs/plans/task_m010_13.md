# Task #13 수행계획서 — upstream-first Studio와 Tauri native HWPX·PDF 저장 통합

GitHub Issue: [#13](https://github.com/postmelee/alhangeul-tauri/issues/13)
마일스톤: M010

## 목적

Alhangeul Tauri의 Studio UI·메뉴·렌더링·문서 lifecycle을 고정된 `rhwp v0.8.2` upstream 구현에 최대한 일치시킨다. Alhangeul macOS가 전체 upstream Studio bundle을 기준으로 native 기능만 보충하는 것과 같은 소유 원칙을 적용하되, Tauri에서는 대규모 host script나 전체 파일 복제 대신 컴파일 시점에 검증되는 얇은 typed adapter를 사용한다.

Windows/Linux 데스크톱 앱에 필요한 native open·save·print·PDF·recent documents·local font·close/dirty guard·file association 경계를 보존한다. upstream 메뉴의 PDF 항목은 Alhangeul의 직접 PDF 저장을 실행하도록 덮어쓰고, upstream에 이미 존재하는 HWPX exporter를 native staging·원자적 저장 경계와 연결해 HWPX 원본 저장과 HWP/HWPX 형식 변환 저장을 제공한다.

## 배경

현재 `apps/studio-host/alhangeul-overrides.ts`는 31개 upstream import를 제품 코드로 shadow하며, 별도 `index.html`, `src/main.ts`, CanvasView, Ruler, Toolbar와 여러 UI/style 복제본을 함께 유지한다. 이 구조는 같은 `rhwp v0.8.2`를 사용하는 Alhangeul macOS·upstream Studio와 메뉴 구성, 초기 문서 위치와 renderer lifecycle이 달라질 수 있게 한다.

upstream `v0.8.2`에는 `exportHwpx()`와 `file:save-as-hwpx`가 있지만 현재 Tauri bridge는 HWPX `Ctrl+S`를 명시적으로 차단하고 Rust commit 계층은 `.hwpx` target을 거부한다. 반면 native PDF 직접 저장, chunked staging, 외부 변경 감지, native recent documents와 로컬 폰트 정책은 Windows/Linux 제품에 필요한 Alhangeul 소유 기능이다. #9는 HWPX 저장 구현과 구조 변경을 제외한 prerelease 후보 검증 Issue이므로 #13을 먼저 완료하고 새 exact-SHA candidate로 #9를 재개해야 한다.

작업지시자는 Windows에서 drag-in이 실제로 정상 동작하며, 초기 문서가 화면 중앙에 보이지 않아 동작 실패로 오인했던 것임을 확인했다. 따라서 drag-in은 결함 수정 대상이 아니라 upstream-first 전환 뒤 보존해야 하는 native 회귀 gate로만 다룬다.

## 범위

### 포함

- `rhwp v0.8.2` exact source의 Studio shell, menu, main lifecycle, CanvasView, Ruler, Toolbar, renderer와 styles를 제품 UI 기준으로 복원한다.
- 수동 복제된 upstream 파일과 alias override를 전수 분류해 upstream 소유, Tauri 필수 adapter, Alhangeul 제품 UX로 구분하고 불필요한 shadow를 제거한다.
- upstream 파일 전체 복사본을 장기 소유하지 않고 exact upstream source와 최소 typed overlay의 차이를 기계적으로 검증할 수 있게 한다.
- Tauri native open, save, save-as, print, direct PDF, recent documents, local font, close/dirty guard, file association와 drag-in 경계를 유지한다.
- upstream `file:print-to-pdf` 메뉴 위치·명령 ID를 유지하면서 실행만 Alhangeul native PDF 직접 저장으로 교체한다. 브라우저 인쇄 기반 PDF 경로는 Tauri runtime에서 실행하지 않는다.
- upstream `file:save`, `file:save-as`, `file:save-as-hwp`, `file:save-as-hwpx`를 native picker와 형식 인식 staging 저장에 연결한다.
- HWP/HWPX별 export, extension·content 검증, chunked staging, atomic replace, 외부 변경 감지, fingerprint·revision·dirty·recent 갱신을 하나의 형식 안전 저장 계약으로 일반화한다.
- HWPX 원본 `Ctrl+S`, 원본 형식 유지 save-as, HWP/HWPX 명시적 형식 변환 저장과 재열기를 검증한다.
- 실패·취소·외부 변경 충돌에서 원본 파일과 dirty/session 상태를 보존한다.
- 현재 정상 동작하는 Windows/Linux drag-in을 구조 전환 후 회귀 검증한다.
- 완료 exact SHA에서 Windows/Linux native candidate와 수용 증거를 만들고 #9 재개 입력을 확정한다.

## 설계 방향

- **upstream-first**: 화면 구조와 일반 Studio 동작의 진실 원천은 `third_party/rhwp/rhwp-studio` exact source다. Alhangeul에서 upstream `index.html`, `main.ts`, view, renderer, toolbar와 범용 dialog의 전체 복사본을 계속 유지하지 않는다.
- **결과 동등성, host 방식 분리**: macOS의 WKWebView host script와 같은 소유 경계를 따르되 Tauri에서는 DOM capture script를 대규모로 복제하지 않는다. source build의 장점을 사용해 명시적 타입과 command ID를 가진 adapter로 native 기능을 주입한다.
- **최소 extension**: upstream main이 native 문서 lifecycle에 필요한 hook을 직접 제공하지 않는 부분은 Stage 1에서 alias 기반 extension, 얇은 bootstrap, 검증 가능한 build-time overlay를 비교한다. 전체 main 복제 없이 테스트 가능하고 다음 upstream pin에서 차이를 탐지할 수 있는 방식을 구현계획서에서 확정한다.
- **메뉴 상속**: upstream `index.html`의 메뉴 구조와 command ID를 기준으로 삼는다. Tauri 전용 별도 메뉴 트리를 유지하지 않고 필요한 command 구현만 교체한다. 제품 표시가 필요한 경우에도 작은 runtime augmentation으로 제한한다.
- **PDF override**: upstream `file:print-to-pdf`의 위치와 활성화 규칙을 상속하되 Tauri runtime의 execute는 현재 native 직접 저장 pipeline으로 연결한다. 실제 인쇄 `file:print`도 Windows/Linux native 경계를 유지한다.
- **형식 안전 저장**: TypeScript와 Rust 양쪽에 동일한 `hwp | hwpx` 형식 계약을 둔다. `exportHwp()` 또는 `exportHwpx()` 결과를 IPC byte payload로 보내지 않고 기존 chunked staging을 사용하며, target extension·요청 형식·파싱 결과가 일치한 뒤에만 atomic replace와 clean 상태 확정을 수행한다.
- **원본 보존**: 외부 변경 확인, expected revision, staging cleanup, atomic write와 fingerprint 갱신 순서를 HWP/HWPX 모두 동일하게 적용한다. 검증 또는 commit 실패 시 기존 target과 current session을 성공 상태로 변경하지 않는다.
- **폰트 정책 보존**: `docs/architecture/LOCAL_FONTS.md`의 system-installed → supported file-backed → bundled substitute 순서와 proprietary font 제외 정책은 변경하지 않는다. upstream font UI/lifecycle과 결합하는 adapter만 최소화한다.
- **drag-in 현상 정정**: drag-in은 정상 기능으로 간주한다. 구현 변경은 native 경계 재결합에 필요한 경우로 제한하고, startup 이후 drop-open과 문서 가시성을 회귀 검증한다.
- **플랫폼 경계**: 플랫폼 중립 TypeScript/build 검증은 현재 호스트에서 수행하되 Rust desktop test, Tauri build, installer/native GUI 수용은 Windows/Linux에서만 수행한다.

## 리스크

- **upstream main extension 부족**: upstream main이 native lifecycle hook을 충분히 노출하지 않아 다시 전체 복사본으로 회귀할 수 있다. Stage 1에서 alias·bootstrap·검증 가능한 build-time overlay를 비교하고 최소 차이와 drift guard를 승인받는다.
- **기능 누락**: 광범위한 override 제거 과정에서 recent documents, local font, close guard 또는 native print가 사라질 수 있다. 소유 matrix와 기능별 adapter test를 제거 전에 고정한다.
- **HWPX round-trip 손실**: exporter가 생성한 HWPX가 원본의 모든 비표준 요소를 보존한다고 가정하지 않는다. 대표 fixture의 parser·page·text·편집 round-trip과 알려진 제한을 검증하고 결과에 따라 공개 기능 설명을 제한한다.
- **형식·확장자 불일치**: HWP bytes가 `.hwpx`에 쓰이거나 반대가 되면 문서 손상이 발생한다. TypeScript 요청 형식, target extension과 Rust parser 결과의 3중 일치 전에는 atomic commit하지 않는다.
- **이중 상태 관리**: upstream document dirty state와 native session revision이 어긋날 수 있다. 저장 완료 이벤트는 native commit 성공 뒤 한 번만 확정하고 실패 경로를 자동 검증한다.
- **large-file 메모리와 IPC**: HWPX export와 save가 큰 문서에서 메모리를 늘릴 수 있다. 기존 chunked filesystem staging을 유지하고 byte IPC를 도입하지 않는다.
- **Task #9 증거 무효화**: UI·저장 구조가 바뀌므로 과거 candidate의 native 기능 증거를 재사용할 수 없다. #13 완료 exact SHA에서 candidate와 필수 gate를 다시 수행한다.
- **플랫폼 검증 가용성**: macOS 호스트에서는 Rust/Tauri native 성공을 주장하지 않는다. Windows/Linux 환경에서 각 Stage의 승인된 native gate를 수행한다.

## 승인 요청 사항

- upstream `v0.8.2` Studio shell·main/view/renderer/menu를 기준으로 하고 Alhangeul의 전체 복제 override를 제거하는 방향
- macOS와 소유 원칙은 맞추되 Tauri에서는 대규모 host script가 아니라 최소 typed adapter를 사용하는 방향
- upstream `file:print-to-pdf` 메뉴 ID를 유지하면서 Tauri에서 native 직접 PDF 저장으로 덮어쓰는 방향
- HWP/HWPX native 저장을 형식 인식 staging·검증·atomic commit으로 일반화하는 방향
- drag-in을 결함 수정 대상에서 제외하고 정상 동작 보존 회귀 gate로만 다루는 범위
- 공식 문서 변경 위치를 `README.md`, `docs/architecture/UPSTREAM.md`, 필요 시 `docs/architecture/LOCAL_FONTS.md`, `docs/operations/DESKTOP_RELEASE.md`로 선택하는 판단
