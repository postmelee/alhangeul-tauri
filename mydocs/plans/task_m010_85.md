GitHub Issue: [#85](https://github.com/postmelee/alhangeul-tauri/issues/85)
마일스톤: M010

작업지시자는 2026-09-30 초안 검토 후 “진행해줘. 작업을 계속진행하고 PR 생성까지 진행해줘.”로
이슈 등록·계획·문서 위치·구현·검증·설정 반영 및 PR 생성까지 계속 진행하도록 명시 승인했다.
이 지시는 이번 작업의 단계별 계속 진행 승인으로 기록하며 PR 병합·이슈 종료는 포함하지 않는다.

## 목적과 범위

첫 stable 공개 상태에 맞춰 사용자 README와 Community Standards를 정비한다.
상세 포함·제외·수용 기준은 승인된 이슈 #85 본문을 기준으로 한다.
README/3개 커뮤니티 문서·기존 bug/feature 폼·chooser·문서 인덱스·저장소 설정에 한정한다.
제품 코드·새 Release/서명/Pages 배포·마케팅 메시지 발송·후속 기능 구현은 제외한다.

## 설계 방향

README에 개발 과정·실행 로그보다 제품 가치와 다운로드를 먼저 제시한다.
실제 기존 OS 스크린샷을 사용하고 출처·라이선스·안전한 문서 제보 링크를 유지한다.
공식 표준 행동 강령과 현재 운영 가능한 연락처·보안 지원 범위를 문서에 반영한다.
개발·릴리즈 명령은 기존 docs 링크로 연결하며 외부 기여 절차를 내부 task 규칙과 혼동하지 않는다.
표준 체크 충족은 실제 GitHub 기본 브랜치 반영 후 확인한다.

## 단계와 승인 범위

1. Stage 1: 사용자 README·커뮤니티 문서. 다운로드·설치·제보 안내와 출처·이미지·문구 검증.
2. Stage 2: 사용자 Issue Forms·chooser·문서 인덱스와 About/토픽/private reporting 설정. 원격 read-back.
3. Stage 3: 통합 문서/기여 동선 검토·최종 보고·devel 대상 Open PR. 기본 브랜치 Community Standards 체크는 병합 후 수용한다.

초안의 “병합 후 설정 반영” 순서는 PR까지만 진행하라는 최신 지시에 맞춰 조정한다.
현재 승인한 정확한 설정값은 Stage 2에서 반영한다. 기본 브랜치의 새 문서 인식은 PR이
병합되기 전 확인할 수 없으므로 최종 체크를 미수용으로 남기고 병합 후 확인하도록 인계한다.
각 단계는 결과 보고와 커밋을 남기며 추가 승인 요청으로 진행을 중단하지 않는다.

## 검증 계획

문서·이미지·다운로드 링크/설치 형식/지원 버전/안내 동선을 확인하고 기존 Issue Form·PR template을 보존한다.
GitHub Community Standards 실제 UI 체크를 우선하고 API는 보조 증거로 대조한다.
원격 설정의 exact read-back, git diff --check 및 해당 기존 빠른 계약 검사로 검증한다.
제품 코드가 없는 작업이므로 native build·서명·패키지 재배포를 반복하지 않는다.

## 리스크

API health percentage와 Issue Forms UI의 인식 범위가 다를 수 있다. 실제 UI를 확인한다.
보안 정책에 응답 시간·장기 지원·보상을 임의 약속하지 않는다.
사용자의 기밀 문서를 upstream 공개 데모나 Issue에 올리도록 유도하지 않는다.
외부 설정은 GitHub 문서 PR과 별도 상태이므로 정확히 추적한다.
