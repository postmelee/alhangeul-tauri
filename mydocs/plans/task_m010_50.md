# Task #50 수행계획서 — Linux HWPX MIME 매칭과 thumbnail 검증 gate 보정

GitHub Issue: [#50](https://github.com/postmelee/alhangeul-tauri/issues/50)
마일스톤: M010

## 목적

제품 DEB/RPM만 설치한 Linux 환경에서 HWPX가 canonical MIME인
`application/x-hwpx`로 해석되고, Nautilus와 Thunar/Tumbler가 제품
thumbnailer를 호출해 실제 첫 페이지 썸네일을 표시하도록 보정한다. 검증용
사설 MIME database가 제품 설치 누락을 가리는 현재 false-positive 경로를
제거한다.

Linux thumbnail core probe는 정상 렌더 결과, process exit, 1,500 ms wall
time과 256 MiB peak RSS를 실제 required gate로 판정하도록 강화한다. 파일
자체 symlink는 계속 거부하면서 정상 Linux 배치에서 사용하는 조상 directory
symlink의 허용 범위를 명시하고 코드·테스트·공식 문서를 일치시킨다.

## 배경

Issue #17과 PR #49는 Linux native thumbnail helper, Freedesktop registration,
DEB/RPM lifecycle 및 Nautilus·Thunar 수용을 도입했다. merge 후 검토에서 다음
세 누락을 확인했다.

- registration과 Tauri file association은 HWPX alias인
  `application/vnd.hancom.hwpx`를 사용하지만, shared-mime-info 2.5 이전에는
  `*.hwpx` 정의가 없고 현재 upstream canonical type은
  `application/x-hwpx`다.
- `scripts/linux-thumbnail-manager-probe.sh`가 실행 직전 private
  `XDG_DATA_HOME`에 `*.hwpx` MIME mapping을 주입해 package 자체로는 성립하지
  않는 HWPX discovery를 통과시켰다.
- `scripts/benchmark-linux-thumbnail-core.sh`는 120초 timeout 여부만 summary
  status에 반영한다. 렌더 실패, 비정상 exit, 1,500 ms 및 256 MiB 예산 초과도
  `passed`가 될 수 있다.
- `apps/linux-thumbnailer/src/cli.rs`는 원본 path와 canonical path의 문자열
  동일성을 강제한다. 입력뿐 아니라 출력 parent의 조상 directory 하나만
  symlink여도 정상 요청을 거부한다.

Freedesktop shared MIME-info specification은 package XML을
`/usr/share/mime/packages`에 설치하고 `update-mime-database`로 glob, magic과
alias cache를 생성하는 확장 방식을 정의한다. Tauri 2.10.1의 DEB/RPM 설정은
custom file과 post-install/post-remove script를 모두 지원하므로 별도 package
toolchain 교체 없이 lifecycle을 구현할 수 있다.

## 설계 방향

- **MIME 진실 원천**: 제품 XML은 canonical `application/x-hwpx` 한 항목에
  `*.hwpx` glob, `application/hwp+zip` mimetype magic 및 upstream과 호환되는
  alias를 선언한다. `.thumbnailer`와 Tauri association은 canonical 이름을
  사용한다. HWP의 기존 `application/x-hwp` 정의는 복제하지 않는다.
- **Package 소유권과 refresh**: XML은
  `/usr/share/mime/packages/alhangeul-hwpx.xml`에 package-owned mode `0644`로
  설치한다. DEB/RPM 모두 Tauri post-install/post-remove script에서
  `update-mime-database /usr/share/mime`를 idempotent하게 실행한다. hook은 MIME
  default, `mimeapps.list`, 다른 XML, thumbnail cache와 process를 변경하지
  않는다. install 도중 refresh가 실패하면 package gate가 실패하도록 하고,
  update/rollback/uninstall 후 cache가 현재 package inventory와 일치하는지
  확인한다.
- **세대 호환성**: shared-mime-info 2.5 미만에서는 제품 XML이 canonical
  HWPX type을 제공하고, 2.5 이상에서는 upstream 동일 type과 병합되어야 한다.
  제거 후에는 제품 XML과 제품이 추가한 mapping만 사라지고 upstream 또는
  제3자 정의는 보존되어야 한다.
- **실제 설치 probe**: manager probe의 `create_mime_database()`와 private XML을
  삭제한다. package-installed `/usr/share/mime`의 `gio info` 결과가
  `application/x-hwpx`인지 기록하고, 그 상태에서만 Nautilus와 Thunar를
  실행한다. evidence에는 private MIME 주입 부재와 installed XML hash를
  포함한다.
- **Core expectation matrix**: 각 record에 기대 성공 여부를 명시한다. 정상
  HWP/HWPX의 `direct`는 성공해야 하며, preview 보유 fixture만 `preview` 성공을
  요구한다. `preview-absent`, 손상, oversize처럼 의도한 negative는
  `success:false`가 기대 결과다. 모든 record는 정상 exit와 hard timeout 부재를
  요구하고, 기대 성공 render는 각각 wall `<=1,500 ms`, peak RSS
  `<=256 MiB`를 만족해야 한다. shell 안전 timeout은 예산에서 크게 벗어난
  process를 회수하는 보조 장치일 뿐 성공 기준이 아니다.
- **실행 가능한 gate test**: inline summary 판정을 재사용 가능한 Node module로
  분리하고 synthetic record fixture로 렌더 실패, exit, timeout, wall, RSS를
  각각 초과시켜 실제 nonzero를 검증한다. source marker 문자열만 확인하는
  테스트를 성공 판정으로 사용하지 않는다.
- **Path 정책**: input/output leaf 자체의 symlink와 non-regular 대상은 계속
  거부한다. 조상 symlink는 parent 또는 input을 한 번 canonicalize해 resolved
  absolute path로 Request에 저장하는 방식으로 허용한다. input/output 동일성은
  resolved path 기준으로 재검사하고 output leaf의 `O_NOFOLLOW`, device/inode 및
  Tumbler precreated-file 방어는 유지한다. 입력과 출력 parent 정책을 함께
  테스트한다.
- **지원 경계**: Windows와 Linux product boundary, direct-first render, 1,500 ms
  worker deadline, 256 MiB worker limit, atomic PNG/Tumbler 예외와 fixture hash는
  변경하지 않는다. AppImage에는 `/usr` MIME side effect를 추가하지 않는다.

## 리스크

- **전역 MIME cache 갱신**: package transaction이 `/usr/share/mime` cache를
  재생성한다. 제품 XML 외 파일·기본 앱·thumbnail cache를 건드리지 않는 hook과
  제3자 sentinel, rollback test로 범위를 제한한다.
- **배포판별 package script 차이**: DEB와 RPM의 install/update/remove argument와
  실패 semantics가 다르다. 같은 idempotent command를 사용하되 각 package의
  실제 lifecycle에서 clean/update/rollback/remove를 독립 판정한다.
- **중복 canonical type**: shared-mime-info 2.5 이상에는 같은
  `application/x-hwpx`가 있다. upstream과 호환되는 alias/glob/magic만 선언하고
  install/remove 전후 old/new database fixture로 병합과 원복을 확인한다.
- **Core negative fixture 오판**: 모든 record에 `success:true`를 요구하면 손상,
  preview-absent와 oversize가 false failure가 된다. fixture/mode expectation을
  data로 기록하고 synthetic test로 분기 누락을 막는다.
- **Symlink 완화의 race**: 조상 symlink 허용이 output leaf 교체 공격까지
  허용해서는 안 된다. canonical parent를 Request에 고정하고 기존
  `symlink_metadata`, `O_NOFOLLOW`, device/inode 재검증을 보존한다.
- **기존 task와 workflow 충돌**: `devel`과 진행 중 task의 workflow·package
  변경을 Stage 진입마다 읽고 Task #50 변경만 최소 반영한다. 다른 branch의
  미완성 변경을 병합하거나 되돌리지 않는다.

## 승인 요청 사항

- 제품이 `/usr/share/mime/packages/alhangeul-hwpx.xml`과 DEB/RPM
  post-install/post-remove MIME refresh를 소유하도록 기존 "system-wide MIME
  database 미변경" invariant를 위 범위로 보정하는 방향
- HWPX canonical type을 `application/x-hwpx`로 통일하고 upstream 호환
  glob·magic·alias를 제품 XML에 제공하는 방향
- core gate를 fixture/mode 기대값과 정상 exit, 1,500 ms, 256 MiB 기준으로
  강화하는 방향
- leaf symlink는 거부하되 input과 output parent의 조상 symlink는 resolved path로
  허용하는 방향
- 5개 Stage, 공식 문서 위치, 검증 matrix와 제외 범위

승인되면 `task_m010_50_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를
구체화한다.
