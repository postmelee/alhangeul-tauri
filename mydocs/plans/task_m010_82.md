# Task #82 수행계획서 — 공개 사이트 안내와 OS별 실제 화면

GitHub Issue: [#82](https://github.com/postmelee/alhangeul-tauri/issues/82)
마일스톤: M010

## 목적

다운로드 제목과 릴리즈 설명을 읽기 쉽게 나누고 제공 목록을 배열에서 생성한다.
Windows/Linux 선택에 맞춰 실제 앱·탐색기 화면 쌍을 전환한다.

## 배경

#69에서 v0.1.0과 Pages를 공개했으나 현재 홈은 Windows 선택 중에도 Linux 이미지만 표시한다.
제목 줄바꿈과 공개 전 안내가 남았다. 사용자 요청으로 디자인은 별도 이슈에서 진행한다.
2026-09-30 작업지시자는 이슈 등록·촬영 계획·구현에 `진행해줘`로 승인했다.

## 범위

### 포함

- 제목 '다운로드' 비분리, 버전 설명과 설치 형식 설명을 두 줄로 분리한다.
- 제공 대상/형식 배열을 순회해 문구·행을 생성하며 version은 release.json을 사용한다.
- 기존 Linux 대표 이미지는 유지한다. Windows는 같은 biz_plan.hwp 첫 페이지, 100%,
  약 1282×924 실제 앱 창을 촬영한다. 테스트 marker를 입력하지 않는다.
- samples 8개를 동일하게 양쪽 탐색기에 배치한다. 첫 페이지 다양성과 실제 생성 여부를 확인한다.
- OS별 앱/탐색기 겹침과 hover/focus/tap 전환, 키보드 및 reduced-motion 지원.
- 캡처 증거·원본 경로·SHA와 최종 채택 여부를 기록한다.

### 제외

제품·rhwp pin 변경, 새 앱 빌드, beta updater 활성화, 실제 썸네일의 합성,
#69 production 조회의 완료 처리, 승인 없는 운영 Pages 배포.

## 설계 방향

Stage 1은 이미 공개된 v0.1.0 bytes만 Windows 2025 hosted runner 및 Ubuntu 22.04 x64
GUI 세션에서 실행한다. 촬영 환경은 제품 지원 대상 OS다. macOS에서는 Node 계약만 검사한다.
기존 final-file verifier와 MSI 설치/정리·WebView2 policy 복구를 재사용한다.
Linux는 동일 ordinary archive의 DEB SHA를 검증한 후 설치해 Nautilus 썸네일을 촬영한다.
Windows Explorer는 hosted 제약으로 실패할 수 있으므로 앱 촬영을 우선하고 사용자 VDI용
8개 파일 묶음을 함께 제공한다. 앱/OS UI를 재그림하거나 이미지로 대체하지 않는다.

샘플은 rhwp v0.8.6 resolved commit f1f9c6ae58344ee9368996d3543f76b9345cf227에 고정한다.
사업계획서·국립국어원 업무계획·form-002·수학·과학·추진일정·막대차트·그림표 8개다.
원문 bytes는 바꾸지 않고 탐색기 이름만 정렬용으로 정리한다.

공개 채널을 추가하는 운영 기능은 만들지 않는다. 제공 목록 데이터와 사용자 문장 생성만
일치시키며 exact URL/서명 계약은 유지한다. 모션은 약 280ms, transform/opacity 중심이다.

## 검증 계획

Stage 1: 후보 hash·fixture 고정, node 계약, shellcheck/actionlint, GUI TypeScript 검사.
실제 촬영은 publish/task82의 exact SHA로 기존 dispatcher site-capture 모드를 실행한다.
이 요청은 촬영용 CI 실행을 포함한다. Actions 완료를 기다리지 않고 run을 전달한다.
결과는 8개 썸네일 생성과 이미지 육안 확인 전까지 채택 미확정으로 둔다.
Stage 2/3: Pages build/check, 기존 상태 fixture 회귀, desktop/mobile·hover/focus/tap·모션 감소 확인.
각 단계 종료 후 결과를 보고한다. 단계별 승인 없이 다음 구현 단계로 진입하지 않는다.
`git diff --check`와 깨끗한 작업 트리, 제품 bytes 불변을 확인한다.
