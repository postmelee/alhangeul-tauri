## 설계 방향

- 기존 Stable tag+commit 동기화 script와 자동 PR allowlist를 우선 사용한다. source·lock·WASM은
  원자적으로 맞추고 generated artifact를 손으로 고치지 않는다. 새 floating dependency를 만들지 않는다.
- Studio의 exact upstream entry와 leaf adapter 소유 경계를 유지한다. core/renderer 복제나 upstream
  backport로 호환성을 우회하지 않는다. 제품 통합의 최소 보정에 필요한 파일만 수정한다.
- 로컬 글꼴 lookup index·재감지·가용성·설정 지속과 provider/session 무효화 계약을 보존한다.
  새 renderer/provider API가 기존 최적화를 우회하는지 계약 검사와 실제 설치본에서 확인한다.
- 신규/변경 모듈은 파일 300 LOC, 함수 50 LOC, 매개변수 5개, 복잡도 10 권장 상한을 따른다.
  상한 초과나 source 보정 범위 확장이 필요하면 구현 전 계획 보정을 요청한다.
- 자동 후보는 Ubuntu Rust preflight까지의 갱신 제안이다. required check·fast 성공과
  Windows/Linux native·새 installer·GUI·공개 수용을 분리한다. 필수 실패·skip·증거 누락을 통과로 바꾸지 않는다.
- 후보 중간에는 자동 preflight와 PR required/fast를 우선 사용한다. 준비 단계의 전체 package 빌드는
  native 통합 수용에 필요한 고정 후보 1회로 제한하고, 반복은 새 source·실패·미해결 우려가 있을 때만 한다.
- source 변경 후 기존 renderer 결과를 재사용하지 않는다. 동일 source/bytes의 증거는 SHA·run·ID/digest·
  환경·관련 diff로 재사용한다. 최종 main에서 새 파일을 만들면 새 hash·서명·설치 수용이 필요하다.
- task PR은 `publish/task113 → devel`, release PR은 `devel → main`이다. 최종 main 승격 전의
  source 수용과 최종 공개 파일의 provenance를 따로 기록한다. 기존 source 수용이 유효하면
  main의 필요한 package 검증만 고르고 원시 검증을 중복하지 않는 근거를 남긴다.
- source/workflow/checkout SHA와 입력 ref를 일치시켜 producer를 고정한다. updater installer 3종은
  성공한 비게시 signed run 하나에서, 수동 package 3종은 같은 source의 일반 producer에서 선택한다.
- 기존 production 공개키·endpoint를 사용한다. Secret 이름·공개 fingerprint만 확인하고 값을 출력하지 않는다.
- 공개는 runbook Gate 3의 exact files 검증 후 수행한다. 검증된 파일을 유지관리자 CLI로 그대로 올리며
  최종 SHA·asset·notes·인증 주체와 그 게시 경로의 공개 승인을 별도로 기록한다.
- Release read-back 후에만 site release data PR·Pages/manifest 공개를 진행한다. 실제 업그레이드를
  수행하기 전에는 notes에 성공을 기재하지 않고, 완료 후 같은 규격으로 결과 안내를 갱신한다.
- 각 단계의 보고·커밋 뒤 다음 단계 승인 요청을 유지한다. 구현계획서에서 Action/PR/merge·서명·공개
  게이트의 입력과 승인 범위를 구체화한다. #113은 릴리즈 전달까지 OPEN 유지한다.

## 리스크

  arm64/Fedora 또는 필수 출력이 미실행이면 다른 플랫폼 성공으로 대신하지 않는다.

  재확인한다. 사용자의 변경을 되돌리거나 기존 automation branch를 덮어쓰지 않는다.
- **공개 provenance**: main 승격·harness 변경·새 빌드는 SHA/bytes를 바꿀 수 있다.
  제품과 harness를 분리하고 승인·검증 입력이 이동하면 최종 파일을 다시 고정한다.
- **알려진 설치 한계**: NSIS thumbnail·MSI 재부팅·Wayland/물리 printer 등의 과거 제한은
  이번 실행 결과와 구분한다. 새 문제나 지원 판단 미결정은 공개 gate 전에 보고한다.
