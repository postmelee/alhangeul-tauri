# Task #28 수행계획서 — devel 보호와 자동 PR 검증

GitHub Issue: [#28](https://github.com/postmelee/alhangeul-tauri/issues/28)
마일스톤: M010

## 목적

개발 수용 브랜치 devel을 PR·GitHub Actions 필수 check로 보호하고, 정상 유지관리자 및 App 후보 PR이 자동 검증을 받을 수 있게 한다.

## 배경

공개 기본은 main, 일반 기여/upstream/Pages는 devel이다. 현재 devel/main 보호와 ruleset이 없고 공개 personal repository의 유일한 maintainer는 postmelee(admin)다. #27의 전체 CI 대기 중 local/task27의 검증 소스에서 분리 준비하되 #27 merge 후 최신 devel을 통합하고 #28 PR을 게시한다. 병행 task90은 수정하지 않는다.

## 범위

### 포함

- devel 대상 pull_request 전용 read-only 자동 CI, 기존 Linux Node/Studio·Windows PS fast 계약 재사용.
- always 최종 단일 필수 check: Alhangeul PR required. 미실행·취소·실패는 fail-closed.
- GitHub Actions app_id=15368에 required check 고정, strict 최신 base, PR 필수·관리자 적용·force push/삭제 금지·conversation resolution.
- lock·HEAD gitlink·Git index gitlink·submodule HEAD 정합성을 local 기본 검증과 PR에서 확인. candidate post-update/pre-commit upstream gate에는 추가하지 않는다.
- 정상 PR·pending/실패 차단·draft 및 App token 후보 경계 검증, 공식 운영/복구 문서, PR 리뷰·병합·이슈 종료·정리.

### 제외

- main 브랜치 승격·보호 적용: 이슈의 적용 대상은 devel이며 기본 main 전환과 release/공개 PR 운영은 유지한다. main에 CI 정의를 승격하지 않은 상태로 required check를 강제하지 않는다.
- 제품/upstream pin/서명/Release/Pages·secret/App credential·organization 변경.
- 새 native 빌드를 자동 PR required gate로 강제하거나 bot 자체 approve/merge를 허용하는 것.

## 설계 방향

- .github/workflows/pr-acceptance.yml에서 pull_request devel의 opened/synchronize/reopened/ready_for_review/converted_to_draft를 받아 draft도 검증한다. path skip은 없다.
- source_ref는 github.sha(merge candidate), contents:read, secrets inheritance 없음, pull_request_target 없음. fork에도 비밀 없는 검사만 제공한다.
- 단일 maintainer의 자기 PR은 다른 사람의 review를 받을 수 없다. required_approving_review_count=0으로 PR 경로와 checks는 강제하고 실제 리뷰는 사용자 승인/PR COMMENT로 남긴다. GitHub APPROVED를 허위 기록하지 않는다. 관리자 bypass는 없다.
- 보호 설정은 .github/protection/devel.json을 먼저 리뷰 가능하게 준비한다. 실제 적용 gate는 #27 병합·#28 PR automatic check 성공·보호 payload 리뷰 후 PUT/GET으로 시행한다. 현재 사용자의 #28 전체 수행·리뷰·병합 지시가 이 목적 내 reversible 보호 적용의 승인 근거다.
- 임시 probe PR에서 필수 check pending/실패의 GitHub BLOCKED 상태, 수정 후 성공을 확인하고 merge하지 않고 close·remote 삭제한다. 제품·보호 devel에 실패 fixture를 병합하지 않는다.
- 새 App token/후보 PR은 secret 발급 없이 기존 실제 App draft PR #78 author/base와 token 최소 권한·draft publish 정의를 대조한다. 새 upstream 릴리즈나 App token 발급은 실행하지 않는다.
- .github/workflows/alhangeul-ci-fast.yml은 기존 jobs를 유지하고 committed pin 검사를 더한다. 기존 대형 파일은 역할을 확대하지 않으며 신규 script/test는 권장 상한 내에 둔다.
