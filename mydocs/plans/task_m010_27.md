# Task #27 수행계획서 — GitHub Actions 의존성 고정

GitHub Issue: [#27](https://github.com/postmelee/alhangeul-tauri/issues/27)
마일스톤: M010

## 목적

모든 외부 Action과 reusable dependency를 upstream 출처가 확인된 full commit SHA로 고정하고, 버전/출처 검토와 floating ref 재유입 방지 검사를 제공한다.

## 배경

2026-09-30 devel a44a48a3 기준 checkout/setup-node major 5·6·7 및 가변 Rust stable이 혼재한다. 기존 task69 미커밋 삭제와 병행 task90을 보존하기 위해 /tmp 분리 worktree local/task27을 사용한다.

## 범위

### 포함

- workflows와 composite action의 모든 외부 uses inventory, upstream tag/commit 확인, 동일 Action의 버전 정렬.
- SHA·version/ref 주석, 기계 inventory 및 Node 정적 검사와 실패 사례 회귀.
- 기존 workflow·권한·입력·job 목적 보존, Windows/Linux 통합 검증, PR 생성·리뷰·병합·정리.

### 제외

- 제품·rhwp pin·updater·서명·공개 파일·Pages 배포 변경, secret 변경, branch protection(#28).

## 설계 방향

- 이미 사용 중인 checkout v7.0.1, setup-node v7.0.0, upload v7.0.1, download v8.0.1을 공식 upstream과 재대조해 전체 정렬한다. cache·App token·Pages는 upstream 공식 release를 확인한다.
- release tag가 없는 dtolnay/rust-toolchain은 stable branch의 exact snapshot으로 고정하고 Rust toolchain stable 정책은 유지한다. Action SHA와 설치되는 compiler version은 다른 계약이다.
- inventory는 .github/action-pins.json, 검사 소유는 scripts/verify-action-pins.mjs. local ./.github 참조는 SHA 변환하지 않는다. 외부 reusable workflow·Docker 참조도 검사의 소유 범위로 둔다.
- 기존 대형 workflow는 구조를 바꾸지 않고 uses·주석만 수정한다. 기존 300 LOC 초과 파일을 새 역할로 확대하지 않는다. 신규 script/test는 권장 상한 내에 둔다.

## 검증 계획

### 단계별 검증

1. GitHub upstream git/ref tag resolved commit과 action.yml 확인, inventory 중복/출처 검사.
2. node --test tests/action-pins.test.mjs, pnpm run test:automation, actionlint, git diff --check.
3. product-boundary·upstream·Studio test/build·GUI typecheck 및 Windows/Linux profile=full. CI_VALIDATION.md의 부분 성공 경계를 유지한다.

### 통합 검증

- 자동 검사는 floating/tag·unknown pin·잘못된 주석·외부 reusable·composite 회귀를 거부한다.
- Windows/Linux full 실제 원격 run과 PR exact head를 확인한 뒤 리뷰·merge한다. 서명/게시 mode는 실행하지 않는다.
- PR 준비 시 clean, diff --check 통과, 기존 권한·입력·제품 경로 불변.

## 리스크

- Action major 정렬은 입력 호환성을 upstream action.yml과 전체 계약·Windows/Linux run으로 확인한다.
- GitHub 기본 main과 개발 devel 차이를 보존하며 task90과 공유 orders가 바뀌면 양쪽 행을 유지한다.
- dtolnay snapshot은 compiler pin이 아니다. 자동 Action 갱신/배포를 추가하지 않는다.

## 승인 요청 사항

사용자가 같은 스레드에서 “#27을 진행해줘. PR 생성 후 리뷰 후 병합 그리고 #28까지 PR 생성 후 리뷰 후 병합까지 진행해줘.”라고 명시했다. 이 수행 범위·기존 공식 docs 루트·3단계·비게시 Windows/Linux 검증·PR 리뷰/병합까지의 진행 근거로 기록한다. 범위를 벗어나는 배포·secret 변경은 포함하지 않는다.
