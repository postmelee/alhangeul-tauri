# Studio desktop adapter lifecycle과 dead bridge 정리 수행계획서

GitHub Issue: [#20](https://github.com/postmelee/alhangeul-tauri/issues/20)
마일스톤: M010

## 목적

Studio의 desktop leaf adapter가 같은 WebView에서 다시 설치되거나 reload되어도 toolbar, Tauri event, Windows wheel listener와 embed handler가 한 세대만 활성 상태로 남도록 설치·교체·해제 수명을 명시한다.

제품에서 더 이상 필요한 호출 경계가 아닌 handler 조회 export, platform hydration과 native platform command를 제거하고, 실제 production consumer가 사용하는 최소 adapter 경계만 유지한다.

## 배경

Task #13과 PR #18에서 exact upstream Studio entry를 유지하면서 desktop 기능을 leaf adapter로 재결합했다. 현재 `CommandDispatcher`는 `installDesktopToolbarModeSync()`의 disposer를 버리고, `ensureDesktopEvents()`는 host별 `Promise<void>`만 보존한다. `setupDesktopEvents()`도 Tauri listener와 Windows wheel reroute의 해제 함수를 수집하지 않아 같은 WebView의 재설치에서 중복 dispatch와 listener 잔존 가능성이 있다. toolbar coordinator 역시 예약된 render가 dispose 뒤 실행되는 수명을 명시적으로 차단하지 않는다.

embed runtime은 module 전역 active handler와 timeout waiter를 직접 관리하지만 설치 교체와 명시 해제를 하나의 registration 수명으로 표현하지 않는다. `getDesktopStudioHandlers()`는 현재 test와 공식 문서에서만 직접 조회하며 production host는 `waitForDesktopStudioHandlers()`를 사용한다. 실제 인쇄의 platform 분기는 `hydrateDesktopPlatform()`을 거쳐 native `desktop_platform` command를 호출하지만 Windows/Linux WebView에서 이미 사용하는 navigator 기반 `detectDesktopPlatform()`과 역할이 겹친다.

이 계획은 [upstream 경계 문서](../../docs/architecture/UPSTREAM.md), Task #13 산출물과 Issue #20의 수용 기준을 기준으로 하며, 최근 문서·PDF job·Windows modified-wheel의 기능 보정과 upstream toolbar/dispatcher 복제는 다루지 않는다.

## 범위

### 포함

- dispatcher 계층이 toolbar coordinator, desktop event, Windows wheel reroute의 disposer를 한 active registration으로 소유하도록 정리
- 비동기 listener 설치 도중 교체·해제되거나 일부 등록이 실패해도 이미 얻은 unlisten/disposer를 회수하는 수명 계약
- 같은 WebView의 반복 setup과 stale disposer 호출에도 최신 registration만 유지되는 idempotent install/uninstall
- toolbar dispose 뒤 예약 render가 product class를 다시 적용하지 않는 cleanup
- embed handler 설치 교체·해제, stale cleanup 보호와 timeout/pending waiter 정리
- production에서 직접 사용하지 않는 `getDesktopStudioHandlers()` export 제거
- `hydrateDesktopPlatform()`과 platform override, native `desktop_platform` Tauri command 제거 후 navigator 기반 Windows/Linux 판정으로 단일화
- reload·중복 setup·부분 실패·stale cleanup을 다루는 focused test와 upstream override boundary 문서·test 정렬

### 제외

- 최근 문서 삭제, PDF job, Windows modified-wheel 동작 자체의 기능 보정
- system print 기능 추가 또는 Issue #15에서 확정한 print surface·modal lifecycle 변경
- upstream toolbar, dispatcher, embed runtime의 복제 또는 `third_party/rhwp` 수정
- 신규 운영체제 지원, release·배포·서명·패키지 게시
- adapter lifecycle과 무관한 native command·TypeScript export 정리

## 설계 방향

- **단일 active generation**: dispatcher adapter 설치를 세대가 있는 composite registration으로 관리한다. 새 설치는 이전 세대의 disposer를 먼저 회수하고, 이전 비동기 설치가 늦게 완료되면 즉시 자기 disposer를 실행한다. stale disposer는 최신 세대를 해제하지 못하게 한다.
- **명시적 event cleanup**: desktop event setup은 `Promise<void>`가 아니라 idempotent disposer를 반환하고, Tauri global/window/close listener와 Windows wheel reroute disposer를 모두 수집한다. 설치 중 실패하면 그 시점까지 등록한 항목을 역순으로 정리한 뒤 오류를 전달한다.
- **toolbar 종료 상태**: coordinator disposer는 event 구독과 product class를 해제하고, 이미 예약된 render callback이 dispose 후 DOM 상태를 되돌리지 못하도록 종료 상태를 확인한다.
- **handler registration 캡슐화**: embed handler의 active 세대, upstream uninstall과 pending waiter timer를 registration 수명 안에서 관리한다. 교체 시 이전 registration을 해제하고, 명시적 종료 시 남은 waiter를 lifecycle 오류로 종료하며 timer와 Set 항목을 함께 제거한다. stale cleanup은 최신 handler를 지우지 않는다.
- **production consumer 기준 삭제**: desktop host는 비동기 handler acquisition만 유지한다. 테스트를 위한 sync getter는 별도 production export로 남기지 않고 public 동작과 disposer를 통해 상태를 검증한다.
- **platform 단일화**: `detectDesktopPlatform()`과 `isTauriRuntime()`은 leaf adapter에 유지하되 hydration cache와 native IPC는 제거한다. 직접 인쇄와 Windows event adapter는 같은 navigator 기반 판정을 사용하며 `unknown`은 플랫폼 전용 보정을 적용하지 않는다.
- **지원 플랫폼 검증**: TypeScript·upstream 경계 검증은 플랫폼 중립 환경에서 수행한다. Rust command registry 변경의 compile/test와 실제 reload 수용은 지원 대상인 Windows/Linux 환경에서만 수행하고 macOS native build 결과를 수용 근거로 사용하지 않는다.
- **크기 경계 유지**: 파일 300 LOC, 함수 50 LOC 권장 상한을 지키도록 listener 등록·cleanup과 handler waiter 종료를 역할별 helper로 분리한다.

## 잠정 단계

- **Stage 1 — dispatcher와 DOM/native event lifecycle 명시**
  - dispatcher의 active registration이 toolbar, Tauri listener, close listener와 Windows wheel disposer를 소유하고 반복 setup·reload·부분 실패에서 이전 세대를 정리하도록 구현한다.
  - dispose 뒤 예약 toolbar render, 늦게 완료된 async setup과 stale disposer가 최신 DOM/listener 상태를 오염시키지 않는지 focused test로 검증한다.
- **Stage 2 — embed handler registration과 waiter lifecycle 정리**
  - handler 설치·교체·해제와 upstream uninstall을 한 registration으로 묶고, sync getter 없이 production의 비동기 acquisition만 남긴다.
  - replacement, 역순 stale cleanup, timeout, 명시적 종료와 재설치에서 handler와 waiter timer가 남지 않는지 검증한다.
- **Stage 3 — dead platform bridge 제거와 경계 통합 검증**
  - 직접 인쇄를 navigator 기반 platform 판정에 연결하고 hydration override와 native `desktop_platform` command를 제거한다.
  - upstream boundary test와 `docs/architecture/UPSTREAM.md`를 실제 handler/platform 소유 경계에 맞춘 뒤 플랫폼 중립 gate와 Windows/Linux native 검증을 수행한다.

## 리스크

- **비동기 설치 경쟁**: Tauri listener 등록 Promise가 교체 뒤 완료되면 오래된 listener가 되살아날 수 있다. 세대 확인과 late disposer 즉시 실행, 부분 실패 rollback을 함께 검증한다.
- **stale cleanup의 최신 상태 파괴**: 이전 dispatcher나 embed runtime의 cleanup이 최신 registration을 지울 수 있다. registration identity를 비교해 소유한 세대만 전역 active 상태를 비우게 한다.
- **toolbar 예약 작업 잔존**: 취소 API가 없는 microtask가 dispose 뒤 실행될 수 있다. callback에서 종료 상태를 확인해 DOM class 재적용을 차단한다.
- **waiter 종료 의미 변경**: 명시적 runtime 종료에서 pending consumer를 계속 대기시키면 timer가 남고, 즉시 거부하면 오류 전달 경로가 바뀐다. lifecycle 전용 오류와 재설치 성공 시나리오를 focused test로 고정한다.
- **platform 오판정**: native IPC 제거 뒤 navigator가 `unknown`이면 Linux print fragment나 Windows wheel 보정이 빠질 수 있다. Windows/Linux WebView의 `platform`과 `userAgent` fixture 및 native 수동 시나리오로 확인하고 `unknown`에는 안전한 공통 동작만 적용한다.
- **지원 범위 밖 검증 오용**: 현재 macOS 작업 환경에서는 Rust desktop/Tauri build를 수용 근거로 실행하지 않는다. native command registry는 Windows/Linux 검증 결과를 별도로 확보한다.
- **공식 문서와 코드 drift**: sync getter 제거 뒤 문서가 이전 API를 계속 설명할 수 있다. architecture 문장과 negative boundary test를 같은 단계에서 갱신한다.

## 승인 요청 사항

- dispatcher 계층이 한 active generation의 composite disposer를 소유하고, 새 setup이 이전 setup을 교체하는 lifecycle 방향
- desktop event setup이 모든 Tauri unlisten과 Windows wheel disposer를 반환하며 부분 실패도 rollback하는 계약
- embed runtime 종료 시 pending waiter를 lifecycle 오류로 종료하고, sync getter를 제거해 비동기 acquisition만 production API로 남기는 방향
- `hydrateDesktopPlatform`과 native `desktop_platform`을 제거하고 Windows/Linux WebView navigator 판정으로 단일화하는 방향
- 공식 문서는 기존 `docs/architecture/UPSTREAM.md`만 최소 수정하고 upstream source와 기능 보정 범위는 제외하는 문서 위치·범위
- 플랫폼 중립 검증과 별도로 Windows/Linux에서 Rust test·Clippy 및 reload 수동 시나리오를 수용 근거로 확보하는 검증 범위

승인되면 `task_m010_20_impl.md`에서 단계별 산출물, 검증 명령, 커밋 메시지를 구체화한다.
