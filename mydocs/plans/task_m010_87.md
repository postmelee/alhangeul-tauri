# 공개 기본 브랜치 전환과 원격 브랜치 정리 수행계획서

GitHub Issue: [#87](https://github.com/postmelee/alhangeul-tauri/issues/87)
마일스톤: M010

## 목적

마케팅 진입점인 저장소 기본 브랜치를 main으로 정렬한다. 공개 이후 승인된 사용자 안내를
main에 반영하고 개발·Pages·upstream 동기화 대상은 devel로 유지한다. 종료된 원격 부산물만 정리한다.

## 배경

main은 공개 제품 fc3cad15이고 현재 기본 브랜치 devel은 1ee2883e다. 이후 #69/#82/#85의
공개 결과·사이트·커뮤니티 안내와 검증 harness가 누적됐다. 제품 경로·lock·rhwp pin은 같다.
열린 #28의 보호 정책 도입과 이번 기본 브랜치 전환을 분리한다.

## 범위

### 포함

- main/devel 및 공개 제품·Release/tag·Pages 환경·workflow·Community 상태 대조.
- 기존 DESKTOP_RELEASE 운영 문서에 공개 기본 브랜치와 개발·배포 대상의 책임을 최소 추가.
- 병합된 automation/rhwp-v0.8.4-full-sync, codex/task14-stage4-probe, publish/task69 삭제.
- 작업 문서 PR을 devel에 반영한 후 devel → main PR을 검토·병합하고 default_branch=main 적용.
- 기본 브랜치의 Community Standards·README·제보·보안·설정 및 기존 공개 사이트 재확인.
- 이슈 종료와 이번 task 부산물 정리, 작업 checkout은 devel로 복귀.

### 제외

- 미병합 publish/task35, 다른 checkout/local/task69 및 main/devel 삭제.
- 제품·버전·pin·lock·v0.1.0 tag·Release asset·서명·updater 변경, 새 build·Pages 배포.
- #28 branch protection·#27 Action pinning 변경, 토큰·Secret 조회/변경, 마케팅 메시지 발송.

## 설계 방향

일반 task PR은 기존 devel 정책을 따른다. 이후 공개 안내 정렬 PR은 devel → main이다.
설정만 먼저 바꿔 사용자 문서 인식이 퇴행하지 않도록 main 반영 후 기본 브랜치를 전환한다.
이미 CI가 통과한 시작 devel tree와 f7b4917a tree가 동일한지 확인하고 이번 문서 전용 변경에
관련 로컬 계약 검증을 수행한다. 기존 Windows·native 증거를 새 제품 검증으로 확대하지 않는다.
삭제는 정확한 remote tip·devel ancestry·열린 PR 및 진행 중 Actions 부재가 확인된 ref에 한정한다.

1. Stage 1 — 기준선·삭제 분류·공식 운영 정책 보완. 제품/CI tree와 문서 위치 검증.

3. Stage 3 — 통합 검토·최종 보고·일반 PR 및 main 승격 PR 준비. 병합 후 설정·실제 UI 수용.

## 리스크

- 기본 브랜치 변경은 예약 workflow 기준과 신규 PR의 기본 base도 바꾼다. checkout/후보 PR은
  명시 devel을 유지하고 기여 안내의 devel 지침과 실제 동기화 설정을 대조한다.
- 미병합 브랜치에는 고유 작업이 있다. publish/task35는 삭제하지 않는다.
- 이미 공개된 v0.1.0 bytes와 이후 문서용 main commit을 혼동하지 않는다. tag와 asset을 보존한다.
- remote ref가 재조회 중 이동하거나 열린 PR/run이 발견되면 해당 삭제를 보류하고 나머지를 진행한다.

## 승인 상태

작업지시자의 같은 스레드 명시 지시 “진행해줘. 그리고 공개된 원격브랜치중 정리해야할 것들도
정리해줘.”는 직전에 제안한 별도 이슈·PR 검토/병합·main 기본 전환·최종 확인 순서와 원격 정리를
승인한 것이다. 이 범위의 단계 보고·커밋·최종 보고·병합·설정 확인까지 진행한다. 범위를 늘리거나
제품/릴리즈를 새로 게시하지 않는다. 새 Actions가 필요하면 완료를 기다리지 않는 사용자 선호를 따른다.
