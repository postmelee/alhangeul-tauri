# Task #135 수행계획서 — SignPath 신청 준비

GitHub Issue: [#135](https://github.com/postmelee/alhangeul-tauri/issues/135)
마일스톤: M010

## 목적
최신 안정 릴리스에 맞게 보안 정책을 갱신하고 실제 데이터 흐름에 근거한 개인정보처리방침을 공개 사이트에 준비한다.

## 배경
2026-11-13 조회한 최신 안정 버전은 v0.1.3이나 SECURITY.md는 v0.1.0을 안내한다. SignPath 신청 전 개인정보 처리와 코드 서명 정책 요구를 구분해야 한다.

## 범위
### 포함
보안 제보 경로 확인, SECURITY.md 최소 수정, 개인정보처리방침 페이지 및 홈페이지·업데이트·문의 페이지 진입 링크, SignPath 요건 조사와 검증 보고.
### 제외
신청 제출, 계정·자격증명 생성, 서명·후원 완료 주장, 제품 동작 변경, 릴리스·배포, upstream 수정, 기존 사용자 변경 수정.

## 설계 방향
v0.1.3 및 origin/devel a3820452를 기준으로 source/config를 확인한다. 자동 업데이트 확인과 사용자가 선택한 다운로드, 로컬 데이터와 외부 서비스 처리를 구분한다. 미확인 미수집·보관 기간·수신 보장은 쓰지 않는다.

## 예상 변경 파일
위 공식 문서와 조사 문서. 신규 페이지의 inventory 증가에 필요한 tests/pages.test.mjs 기대 개수 갱신. 작업 산출물은 mydocs/orders/20261113.md, plans/task_m010_135{,_impl}.md, working/task_m010_135_stage{1,2,3}.md, report/task_m010_135_report.md.

## 잠정 단계
- Stage 1: release·제보·데이터 흐름과 SignPath 요건 조사.
- Stage 2: SECURITY.md와 사이트 정책·링크 작성.
- Stage 3: 사이트 검증·빌드·최종 보고.

## 검증 계획
Stage 1은 source와 공개 원문 대조. Stage 2는 링크와 문구 대조. Stage 3은 pnpm run check:pages, pnpm run build:pages, node --test tests/pages.test.mjs, git diff --check. 문서만 바꾸므로 Rust/Tauri와 OS 앱 실행 검증은 하지 않는다. 사이트 배포도 하지 않는다.

## 리스크
비공개 제보 UI의 인증/설정과 이메일 수신은 실제 제보 없이 확정 불가할 수 있다. 외부 서비스의 보관·처리는 해당 정책을 연결한다. 시작 시 통신과 SignPath 설치 시 안내/옵션 요구의 적용 여부는 신청 전 확인 사항으로 남긴다.

## 승인 및 진행 근거
최초 이슈 등록 후 단계 승인을 요청했고, 후속 지시에서 “기존 사용자 변경을 보존하며 task-start와 계획·구현·검증을 이어가 주세요”를 명시했다. 이 범위의 진행 지시를 적용한다. PR 게시·merge·신청 제출은 이번 진행 범위에 포함하지 않는다.
