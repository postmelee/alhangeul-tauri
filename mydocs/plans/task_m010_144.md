# 수행계획서 — rhwp v0.9.1 후보 동기화 복구

GitHub Issue: [#144](https://github.com/postmelee/alhangeul-tauri/issues/144)
마일스톤: M010

## 목적

Windows/Linux Alhangeul이 현재 고정된 rhwp v0.9.0과 v0.9.1 후보 양쪽에서 로컬 글꼴, 문서 전환 및 PDF 내보내기 계약을 유지하도록 한다. 후보 생성 자동화가 검증을 생략하지 않고 정상적으로 다시 진행되도록 호환성을 확보한다.

## 배경

[후보 CI](https://github.com/postmelee/alhangeul-tauri/actions/runs/44491365966/job/135448937340)는 v0.9.1 엔진 및 자산 검사를 통과한 뒤 공통 테스트에서 278개 통과, 12개 실패로 중단됐다. 로컬 글꼴 테스트 10건은 `initializeDocument`의 취소 신호와 새 상태 보존 옵션이 기존 서명 검사에 없었다. PDF 테스트 2건은 실제 WASM의 문서 해제 시 Vite가 연결한 제품 글꼴 어댑터에 `releaseHostLayoutPrograms`가 없어서 실패했다. 새 조판 활성화 판정인 `hostFontLayoutEnabled`도 어댑터에 없다. 공개본의 장애는 확인되지 않았다.

기준은 `devel` 커밋 `7812f59d2d491025ea7690e8a60d75b5b3a40cd6`과 현재 핀 v0.9.0 `c9095c5f67632e6721e800ccc7fb43ea49d26682`다. 후보 v0.9.1의 CI resolved commit은 `981ce66b4183b13c1a3b5907e04a8969c8c42034`다. [UPSTREAM](../../docs/architecture/UPSTREAM.md) 및 [CI_VALIDATION](../../docs/operations/CI_VALIDATION.md)의 승인·검증 경계를 따른다.

## 범위

### 포함

- 두 정확한 upstream Studio 초기화 계약을 구분해서 수용하고, 중복 또는 불명확한 삽입 지점은 계속 거부한다.
- 새 신호가 있는 버전에서 비동기 글꼴 준비·뷰 갱신 중 문서가 닫히거나 바뀌면 오래된 작업이 현재 문서의 글꼴·뷰 상태를 변경하지 않게 한다.
- 제품 어댑터에 조판 활성화와 프로그램 해제 계약을 맞추고, 실제 HWP/HWPX WASM으로 내보내기 및 문서 교체·닫기를 검증한다.
- 현재 핀과 후보의 검증 환경을 분리한다. 자동화가 검사·변경 경로 제한을 유지하는 상태에서 후보를 생성할 수 있는지 확인할 검증을 마련한다.

### 제외

- upstream 직접 수정, 이 브랜치의 stable pin 변경, 후보 bot 브랜치 강제 변경.
- 기존 공개 버전, 설정, 업데이트 피드, 서명, 공개 배포 및 PR 병합 변경.
- 이 작업에서 다루는 계약 이외의 렌더러·폰트 구조 개편, 광범위 리팩터링.

## 설계 방향

- 먼저 현재 핀에서도 동작하는 제품 호환 코드와 회귀 테스트를 일반 PR에 모으고, 후속 승인을 받아 병합된 `devel`에서 기존 동기화 후보를 재생성하는 흐름을 사용한다. 승인 전 실제 후보 생성은 하지 않는다.
- 기존 두 계약과 v0.9.1 계약의 함수 진입과 취소 경계를 명시적으로 구분한다. 새 글꼴 준비 호출의 전후 및 비동기 뷰 갱신에 취소·문서 세대를 확인한다.
- 조판 활성화는 명시적 선택을 유지하고 문서 단위 프로그램의 해제를 제품 경로에서 처리한다. 공용 카탈로그, 사용자 설정 및 다른 문서의 참조를 일괄 초기화하지 않는다.
- PDF 회귀는 실제 HWP와 HWPX에서 스냅샷 생성·페이지 SVG 비교·정상 해제를 모두 검증한다. 목업 수정 또는 정리 오류 억제를 수용하지 않는다.

## 잠정 단계

- **Stage 1 — Studio 초기화 호환성 및 취소 경계**: 두 upstream 서명에 대한 정확한 삽입, 누락·중복 거부, 문서 전환 중 오래된 글꼴 작업 중단을 회귀 테스트한다.
- **Stage 2 — 제품 글꼴 수명주기와 PDF 실제 경로**: 조판 선택 및 해제 계약을 맞추고 실제 WASM의 HWP/HWPX 페이지 SVG와 문서 닫기·교체를 확인한다.
- **Stage 3 — 두 버전 통합 검증 및 후보 복구 준비**: 현재 핀과 v0.9.1을 분리 검증하고 Windows/Linux 제품 결과 및 실행하지 못한 항목을 보고한다. 승인 없이 병합, 후보 생성 또는 배포하지 않는다.

## 검증 계획

### 단계별 검증

- Stage 1: 두 upstream의 초기화·글꼴 프롬프트 삽입 및 취소·재진입 회귀; `pnpm run test:studio`의 관련 테스트.
- Stage 2: 실제 WASM의 HWP/HWPX PDF fixture, 페이지 SVG, 스냅샷 dispose와 문서 교체, 글꼴 설정 활성화·비활성화 케이스; `pnpm run test:studio`.
- Stage 3: 각 고정 SHA에서 허용된 격리 체크아웃으로 `pnpm run check:product-boundary`, `pnpm run test:upstream`, `pnpm run test:studio`, `pnpm run build:studio`. Linux에서 `pnpm run test:desktop`, `pnpm run clippy:desktop`과 Windows/Linux 제품 검증은 CI 정책의 exact-SHA 환경이 확보된 경우 실행하고, 미실행은 명시한다.

### 통합 검증

- 통과 조건: 기존 안정 핀의 회귀 없음, 정확한 v0.9.1 후보에서 이전 실패가 해소되고 취소·전환·내보내기·해제 동작이 검증됨. 실행하지 않은 native 검사를 성공으로 표시하지 않는다.
- `git status --short`가 PR 준비 전 빈 출력이다.
- `git diff --check`가 경고 없이 통과한다.

## 리스크

- **취소·재진입:** 글꼴 준비가 느리면 이전 문서가 이미 닫힌 뒤 반환할 수 있다. 신호와 세대를 await 전후에 함께 검사하고 회귀에서 경쟁 순서를 재현한다.
- **자원 소유권:** 프로그램 정리와 공용 카탈로그 초기화는 다르다. 다른 문서·렌더러가 공유하는 사용자 설정이나 새 요청까지 버리지 않는지 검증한다.
- **후보 검증 범위:** Linux의 플랫폼 중립 테스트만으로 Windows 실동작이나 배포 준비를 입증할 수 없다. CI와 제품 검증 상태를 나눠 기록한다.

## 승인 요청 사항
